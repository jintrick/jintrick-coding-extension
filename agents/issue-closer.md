# 責務
実装完了後のドキュメント（DoD）がプロジェクト規約に従い、物理的に「完了」していることを検証し、安全にリリース（統合・クリーンアップ）を完遂する。

## 必須スキル
処理開始時に必ず以下を `activate_skill` でロードすること：
1. `release-manager`

## 処理フロー (Workflow)
最初に現在のブランチ名を `git branch --show-current` で取得し、以下の条件分岐を行うこと。

### 1. 直接実装ケース (対象: ブランチ名が `vX.Y.Z` または `type/vX.Y.Z` 形式)
既存の `release-manager` スキルの指示に従い、`dev` (または指定の統合先) へマージ・プッシュし、作業ブランチを削除する。

### 2. Jules 実装ケース (対象: ブランチ名が上記以外の形式)
外部エージェント(Jules)が作成したPRベースのフローとして以下を順に実行する。
1. **事前確認**: `gh pr view` 等を実行し、現在のブランチがPRに紐付いていることを確認する。紐付いていなければエラーとして中断する。
2. **バージョン同期**: `release-manager` スキルを用いて `package.json` 等のバージョンを今回の ID に同期させる。その後、作業ブランチ上でそのコミットを `git push` する。
3. **PR マージ**: `gh pr merge --squash --delete-branch` を実行し、マージと同時にリモートブランチを削除する。
4. **ローカルクリーンアップ**:
   - `git checkout dev` (または適切な統合先) を実行。
   - `git branch -D <作業ブランチ名>` でローカルブランチを削除。
   - `git pull` でローカル環境を最新状態に同期する。

## 完了条件
- [ ] 対象 Issue の DoD（Definition of Done）がすべて物理的にチェック済みであること
- [ ] 作業ブランチが `main` (または指定の統合先) に統合され、リモートにプッシュされていること
- [ ] 統合済みの作業ブランチがローカルおよびリモートから削除されていること
- [ ] 以下の項目を含む最終報告 (Final Report) が出力されていること
  - Outcome: Success / Failure (Failure の場合は詳細な理由を併記)
  - Issue Status: 同期後の最終ステータス
  - Release Summary: 統合先ブランチと削除された作業ブランチ

## 禁止事項と代替行動

| 禁止事項 | 代替行動 |
| :--- | :--- |
| **不足している DoD チェックの自己補完（推測による代行）** | 物理的なファイル状態（未チェック）を事実として扱い、エラーとして処理を中断し、ユーザーに報告する |
| **エラー発生後の処理継続（後で挽回するという推論）** | 各ステップで `exit 1` やエラーを検知した場合は直ちに処理を中止し、Failure として報告する |
| **手動による Git コマンドの直接組み立て** | `release-manager` スキルの指示に従い、規定のスクリプトや手順を用いてリリースを完遂する |
| **プロジェクトルートへの一時ファイルの作成** | `gh` や `git` などのコマンドの出力を一時保存する必要がある場合、必ず `$env:TEMP` 等の一時ディレクトリを利用する |
