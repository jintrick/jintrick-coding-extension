# Issue: issue-closer サブエージェントの自律調査禁止と役割の純粋化

## 背景と問題点
現行の `issue-closer` は、DoD（Definition of Done）のチェックが漏れている場合に、自ら `grep_search` 等を用いてコードベースを調査し、チェックを補完しようとする「暴走」挙動が確認された。これはサブエージェントの役割（Git操作と事務手続き）を逸脱しており、メインエージェントとの責任境界を曖昧にする。

## 解決策
1. `agents/issue-closer.md` の `tools` から `grep_search` を物理的に削除する。
2. プロンプトを改訂し、「DoD 不備発見時の即時エラー終了（FAIL FAST）」を厳命する。
3. `issue-closer` を「内容の妥当性判断」ではなく「チェックボックスの状態（物理的事実）」のみを監視する「執行官」として再定義する。

## 実装内容詳細
- **物理的な権限剥奪**:
  - `agents/issue-closer.md` のフロントマター `tools` 配列から `grep_search` を削除する。
- **プロンプトの厳格化**:
  - 「未チェックの `- [ ]` 項目が一つでも存在する場合、1ミリも調査（コード確認等）を行わず、即座にエラーとして終了し、メインエージェントに差し戻すこと」を命令文に追加する。
  - 推論による自己補完を「致命的な規約違反」として定義し、禁止する。
- **役割の再定義**:
  - `issue-closer` の存在意義は「完了状態の機械的な確認」と「Git コミット/プッシュの代行」に限定されることを明記する。

## 規約準拠 (Rule Compliance)
- [comment-preservation.md] -> プロンプトの改訂にあたり、既存の設計思想や「なぜこの制約があるのか」という文脈を損なわないよう、変更の意図を明確に反映した記述を行う。
- [no-temp-files-in-root.md] -> 本件はプロンプトおよびメタデータの修正のみであり、一時ファイルを生成するロジック変更は含まないため、準拠に問題なし。

## ゴール
- `issue-closer` が自律的な調査行動（`grep_search` 等）を一切行わなくなること。
- DoD の不備に対して一切の忖度をせず、機械的にエラーを返却することで、メインエージェントによる修正を強制できること。

## テスト
- **テスト対象**: `issue-closer` の DoD チェックロジック
- **テスト内容・目的**: 未チェック項目がある場合に自律調査を試みず、即座に Failure を報告することの検証
- **検証方法・手順**: 
  - [x] 未完了タスク (`- [ ]`) が残っている Issue を `issue-closer` に渡す。
  - [x] `issue-closer` が `grep_search` を呼び出す形跡がないことを確認する。
  - [x] `issue-closer` が即座に「DoD が未完了である」旨のエラーメッセージを出力して終了することを確認する。

## Appendix: 技術的選定理由 (Why/Why Not)
単純なプロンプトの修正（Soft Constraint）だけでは、大規模言語モデルの性質上「親切心」による補完を完全には防げない可能性がある。そのため、ツール定義（`tools`）から物理的に `grep_search` を奪うことで、物理的な制約（Hard Constraint）を課す。
