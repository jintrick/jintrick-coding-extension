# Issue: Markdown Human Linter のリファクタリング（VBScript 廃止と OS 標準オープナーの採用）

## 背景と問題点
現在の `Markdown Human Linter` (`hooks/scripts/linters/md.cjs`) は、Windows 環境においてエディタをデタッチ起動するために一時的な VBScript ファイルを生成・実行している。これは以下の点で改善の余地がある：
- 一時ファイル（`.vbs`）の管理コストと、`wscript.exe` への依存。
- Linux/macOS 環境において、環境変数 `EDITOR` に依存しており、デスクトップ環境の標準オープナー（`xdg-open`, `open`）が活用されていない。

## 解決策
VBScript による起動ロジックを廃止し、Node.js の `child_process.spawn` を用いて、各 OS の標準的な方法でエディタをデタッチ起動するようにリファクタリングする。

## 実装内容詳細
### 1. Windows 環境の起動ロジック刷新
- `child_process.spawn` を使用し、`cmd /c start` を介してエディタを起動する。
- 以下のオプションを指定して、プロンプト（黒い画面）を表示させず、かつ Gemini CLI をブロックしないようにする：
  - `detached: true`
  - `stdio: 'ignore'`
  - `windowsHide: true`
- 起動後に `child.unref()` を呼び出し、親プロセスから完全に切り離す。

### 2. Linux / macOS 環境の標準オープナー対応
- OS に応じて適切なコマンドを選択する：
  - macOS (`darwin`): `open`
  - Linux (`linux`): `xdg-open`
- `spawn` を用いてこれらのコマンドを実行し、非同期でデタッチ起動する。

### 3. 不要なコードの削除
- VBScript ファイルの生成ロジック (`launcher_*.vbs`) および `wscript.exe` の呼び出し部分を完全に削除する。
- 不要になったモジュールや一時変数があれば整理する。

## 規約準拠 (Rule Compliance)
- **comment-preservation.md** -> リファクタリングに際し、既存の JSDoc 形式のドキュメントや、技術的な背景を説明するコメント（デタッチ起動の意図など）を維持・更新する。
- **no-temp-files-in-root.md** -> 既に `os.tmpdir()` を使用しているが、VBScript ファイルの生成を廃止することで、一時ファイルそのものを減らし、よりクリーンな実装とする。

## ゴール
- Windows 環境で黒い画面を出さずにエディタをデタッチ起動できる。
- Linux/macOS 環境で OS 標準のアプリケーションでプレビューを開くことができる。
- 不要な一時ファイル生成が排除され、コードの保守性が向上する。

## テストと検証要件 (Testing & Verification)

過去の不具合（v1.26.0: エディタが CLI をブロックする問題）の再発を確実に防ぐため、以下の 3 つの観点で検証を行う。

### 1. 非ブロッキング検証 (Non-blocking Check) - 最優先
- **目的**: エディタが開いている間も Gemini CLI が次の操作を受け付けられることを確認する。
- **手順**:
  1. Windows/Linux 環境で Markdown ファイルを編集し、Linter を起動させる。
  2. エディタ（Notepad 等）が開いた状態のまま、ターミナルに戻る。
  3. **確認事項**: エディタを閉じる前に、Gemini CLI の応答（例: `Decision: allow` の表示や、次のプロンプトの出現）が即座に返っていること。
  - *NG挙動*: エディタを閉じるまでターミナルが「待機状態」になり、次の操作ができない。

### 2. プロセス独立性検証 (Process Independence)
- **目的**: Linter Hook（親プロセス）が終了しても、エディタ（子プロセス）が閉じないことを確認する。
- **手順**:
  1. Linter を起動し、エディタが開いたことを確認する。
  2. ターミナルで Linter Hook プロセスが終了したことを確認する（CLI がプロンプトに戻る）。
  3. **確認事項**: エディタが強制終了されず、そのまま残っていること。

### 3. UI/UX 検証 (Windows Only)
- **目的**: 起動時に余計なコンソールウィンドウ（黒い画面）が表示されないことを確認する。
- **手順**:
  1. Windows 環境でエディタを起動する。
  2. **確認事項**: 起動の瞬間にコマンドプロンプト（cmd.exe）が一瞬でもフラッシュ（表示）されないこと。
