# Issue: Antigravity 互換・動的プロンプト・コンパイラ & 完了通知システムの構築

## 概要
Gemini CLI の `BeforeModel` フックを活用し、Claude Code 由来の動的プロンプト合成アーキテクチャを移植する。また、`AfterAgent` フックを用いてタスク完了を Windows 標準のトースト通知で知らせるシステムを構築する。

## 背景と問題点
1. **固定システムプロンプトの限界**: 静的な指示では履歴の増大に伴い規約を忘れる（Loss in the Middle）傾向があり、状況に応じた指示の最適化が困難。
2. **Antigravity との乖離**: IDE 側の法典（`.agent/rules/`）と CLI 側で規約が共有されておらず、一貫性の欠如が生じている。
3. **長時間の待機コスト**: 高度な推論や大量のファイル操作を伴うタスクにおいて、完了を画面の前で待つ必要があり、開発効率が低下している。

## 解決策
1. **動的プロンプト・コンパイラ (BeforeModel)**: 実行コンテキスト、アクティブなルール、セッションフェーズに基づき、System Message を毎ターン動的に再構成する。
2. **Windows Toast Notification (AfterAgent)**: エージェントの全処理が完了した際、Windows 標準の通知センターおよびサウンドでユーザーに通知し、非同期作業を支援する。

## 実装内容詳細

### フェーズ 1: ワークスペース・ルール・スキャナー (BeforeModel)
- `.agent/rules/*.md` を探索し、YAML フロントマターから適用条件（Always/Glob/Manual）を抽出。
- 高速化のためのインクリメンタル・キャッシュ戦略を実装。

### フェーズ 2: コンテキスト・インジェクション
- Claude Code (v2.1.69) 由来のエンジニアリング思想とアクティブなルールを `messages[0]` に注入。
- 4,000 トークンの予算管理に基づく優先度付きパージ。

### フェーズ 3: 状況依存型リマインダーと変数置換
- `PLANNING` / `IMPLEMENTATION` モードを自動判定し、最新メッセージ直前に System Reminder を注入。
- `${CWD}`, `${AvailableTools}`, `${CURRENT_BRANCH}` 等の動的置換。

### フェーズ 4: 完了通知システム (AfterAgent)
- **トリガー**: `AfterAgent` フック。
- **実装**: PowerShell を介した Windows Runtime (WinRT) 直接呼び出し（依存モジュールなし）。
- **通知内容**: タスク完了の成否、要約、および実行時間をトーストで表示。

## ゴール
- `.agent/rules/` 内の規約が正しくプロンプトに反映され、LLM がそれに従うこと。
- トークン予算を超えた場合、優先度の低いルールが適切に削除されること。
- 全てのツール実行と回答が終わった瞬間に、Windows のトースト通知が届くこと。
- フック全体のオーバーヘッドが 100ms 前後（理想はそれ以下）に抑えられること。
