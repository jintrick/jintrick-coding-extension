# Issue: Windows 標準トーストによるタスク完了通知システムの構築

## 概要
Gemini CLI の `BeforeAgent` および `AfterAgent` フックを利用し、タスク完了時に Windows OS 標準のトースト通知を発火させる機能を実装した。これにより、長時間実行されるタスクの終了をバックグラウンドで待機可能にした。

## 背景と問題点
- **待機コスト**: コード生成や大規模リサーチなどの長時間タスクにおいて、ユーザーがターミナルを注視し続ける負荷。
- **環境制約**: Windows 環境における WinRT 呼び出しの不安定さ、およびフックのライフサイクルとタスクの定義の不一致。

## 最終的な解決策（決定事項）
1. **イベントの最適化**: ツール実行による多重発火を避けるため、`BeforeAgent` (入力時) で計測開始、`AfterAgent` (最終回答時) で通知を行う構成とした。
2. **ロックファイル方式**: `hooks/cache/${session_id}.lock` という空ファイルの生成時刻（mtime）を起点とし、JSON パース等のオーバーヘッドを完全に排除した。
3. **一時ファイル実行方式**: 文字コード（BOM）やデコードの不安定さを伴う `-EncodedCommand` を廃止し、物理的な `.ps1` ファイルを動的に生成・実行する方式を採用。
4. **AppId の借用**: Windows OS 側での通知ブロックを回避するため、PowerShell 本体の AppId (`{1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}...`) を借用。
5. **同期実行の採用**: バックグラウンド実行（unref）時のプロセス消滅を回避するため、`spawnSync` により通知の確実性を担保した。

## 受け入れ基準 (Acceptance Criteria) - 最終結果

- [x] **AC 1: Windows WinRT 通知の実装**: PowerShell 5.1 を介して WinRT API を呼び出し、トースト表示に成功。
- [x] **AC 2: ロックファイル方式による軽量な状態管理**: 10秒フィルタの実装と、セッション固有ファイルによる正確な時間計測を実現。
- [x] **AC 3: 堅牢なプロセスコントロール**: 一時 `.ps1` ファイルと `spawnSync` の組み合わせにより、不確定要素を完全に排除。
- [x] **AC 4: フックの登録**: `hooks/hooks.json` および `tools/build.cjs` への正しい登録を確認。

## 実装の変遷と教訓 (Post-Mortem)
- **Phase 1 (失敗)**: `BeforeModel` を起点とした。ツール使用時に時間がリセットされる不備。
- **Phase 2 (失敗)**: `-EncodedCommand` で Base64 文字列を渡したが、環境依存でサイレントに失敗。
- **Phase 3 (失敗)**: `detached: true` で非同期起動したが、Node.js プロセス終了とともに通知プロセスも消滅するケースが発生。
- **Phase 4 (成功)**: `BeforeAgent` への移行、物理ファイル実行、AppId 借用、`spawnSync` の採用。
