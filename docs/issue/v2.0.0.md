# Issue: Windows 標準トーストによるタスク完了通知システムの構築

## 概要
Gemini CLI の `AfterAgent` フックを利用し、タスク完了時に Windows OS 標準のトースト通知を発火させる機能を実装する。これにより、長時間実行されるタスクの終了をバックグラウンドで待機可能にする。

## 背景と問題点
- **待機コスト**: コード生成や大規模リサーチなど、完了まで数十秒から数分かかるタスクにおいて、ユーザーはターミナルを注視し続ける必要がある。
- **視認性の欠如**: ターミナルの出力が止まっただけでは、エラー停止か正常終了かの判別が遠目には困難である。

## 解決策
1. **WinRT Notification (AfterAgent)**: `AfterAgent` フックにて、PowerShell 5.1 を使用して Windows Runtime (WinRT) を呼び出し、トースト通知を表示する。
2. **非同期実行**: 通知処理をバックグラウンドで実行（detached/unref）し、CLI 本体の終了や次の入力待ちをブロッキングしないように制御する。

## 受け入れ基準 (Acceptance Criteria)

### AC 1: Windows WinRT 通知の実装
- [ ] `AfterAgent` フックにて、PowerShell 5.1 を介して以下の WinRT クラスを呼び出し、通知を表示すること：
    - `Windows.UI.Notifications.ToastNotificationManager`
    - `Windows.Data.Xml.Dom.XmlDocument`
- [ ] 通知内容に以下の動的な情報を含めること：
    - タイトル: 「Gemini CLI: [プロジェクト名]」（Git リポジトリ名、またはカレントディレクトリ名から自動取得）
    - 本文: 「タスク完了: 実行時間 [秒]s, [成否ステータス]」
- [ ] 通知の「AppId」を適切に設定し、Windows の通知設定で制御可能にすること。

### AC 2: ロックファイル方式による軽量な状態管理 (10秒フィルタ)
- [ ] 実行時間が **10秒（10,000ms）以上** かかった場合のみ通知を表示すること。
- [ ] 実行時間は以下の「ロックファイル方式」で算出すること：
    1. `BeforeModel` フックにて、ファイル `hooks/cache/${session_id}.lock` が存在しない場合のみ空ファイルを作成する（タスク全体の開始時刻を固定）。
    2. `AfterAgent` フックにて、同ファイルの `mtime`（更新日時）を取得し、現在時刻との差分を計算する。
    3. 計算後、直ちにファイルを削除（unlink）し、状態をクリーンアップすること。
- [ ] 巨大な JSON のパースや、単一ファイルへの I/O 競合を完全に排除すること。

### AC 3: 完全な非同期プロセスの分離
- [ ] PowerShell の起動には `child_process.spawn` を使用し、以下のオプションを指定すること：
    - `detached: true`
    - `stdio: 'ignore'`
    - `unref()`
- [ ] これにより、通知処理の起動ラグ（PowerShell の初期化等）が CLI の応答時間に影響を与えない（50ms 未満）ことを保証すること。

### AC 4: フックの登録
- [ ] `hooks/hooks.json` に `BeforeModel` および `AfterAgent` イベントに対するフックを正しく登録すること。
