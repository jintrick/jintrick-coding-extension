# Issue: 通知フックの拡張（AppID 競合回避による即時通知の実現）

## 概要
エージェントが `ask_user` で待機する際、Windows による通知抑制を回避し、思考中であっても即座にトースト通知を表示させる。これにより、開発の停滞を物理的に解消する。

## 背景と問題点（検証済み事実）
現在の `toast_notification_hook.cjs` は PowerShell の標準 AppID を使用している。
Windows OS は、現在アクティブなウィンドウ（ターミナル）と同一の AppID を持つプロセスからの通知を「ユーザー操作の邪魔」と判断し、プロセスがアイドル（ターン終了）になるまでトーストの表示を抑制（保留）する挙動がある。
このため、`BeforeTool` (ask_user) で通知を送っても、ユーザーが回答を終えるまで通知が表示されないという本末転倒な事態が発生していた。

## 解決策: AppID Hijacking による抑制の突破
ターミナルのプロセスツリーとは無関係な AppID を使用することで、OS の抑制ロジックをバイパスし、即時表示を強制する。

1.  **AppID の変更**:
    - 通知に使用する `$appId` を `Microsoft.Windows.Explorer` 等の独立したシステム ID に変更する。
2.  **プロセスの完全分離（Async & Detached）**:
    - `spawnSync` を `spawn` に変更し、`detached: true` で実行。
    - フックは通知の完了を待たずに即座に `allow` を返し、CLI の UI レンダリング（ダイアログ表示）を優先させる。
3.  **セッションタイマーによる最適化**:
    - `JINTRICK_TOAST_THRESHOLD_MS`（30s）以上の独走思考があった場合のみ通知をトリガーする（既存ロジックの継承）。

## 実装内容詳細

### 1. 聖典の遵守 (Strict Compliance)
`docs/reference/hooks-spec.md` に規定されたイベント・キー名を正確に使用し、副作用（通知）によってエージェントのメインフローを妨げないこと。

### 2. `toast_notification_hook.cjs` の修正
- **`showToast` 関数**:
    - `$appId` を `'Microsoft.Windows.Explorer'` に固定。
    - `spawnSync` を `spawn` (options: `{ detached: true, stdio: 'ignore', windowsHide: true }`) に置換。
    - `child.unref()` を呼び出し、フックプロセス終了後も通知プロセスを維持。
- **PowerShell スクリプト**:
    - 通知登録の確実性を担保するため、末尾に `Start-Sleep -Milliseconds 500` を追加。

## 受入基準 (Acceptance Criteria)
- [ ] **即時性**: 30 秒以上の思考後、`ask_user` ダイアログが表示されるのと**同時、あるいはその直前**にトーストが表示されること。
- [ ] **非抑制**: エージェントが思考中（回答生成中）であっても、通知が表示されること。
- [ ] **安定性**: ターン終了後に「溜まっていた通知」がまとめて表示されないこと。
- [ ] **整合性**: `AfterAgent` での完了通知も、新しい AppID を用いて正常に機能すること。
