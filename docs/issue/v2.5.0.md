# Issue: 通知フックの拡張（ask_user 待機状態への Deterministic な対応）

## 概要
エージェントが `ask_user` を呼び出し、ユーザーの入力を待機する際、エージェントの独走（思考）時間が閾値を超えている場合にのみトースト通知を送信する。これにより、対話の停滞を最小化し、かつ通知のノイズを排除する。

## 背景と問題点
現在の `toast_notification_hook.cjs` はタスク完了時（`AfterAgent`）のみを対象としている。
エージェントが長時間思考した後に `ask_user` で停止した場合、ユーザーが画面から離れていると開発がストップする。一方で、単純な `BeforeTool` での通知は、頻繁なやり取りにおいて過剰な通知（Noisy）となる。

## 解決策: 「最終操作時刻」ベースのスマート通知
「ユーザーとの最終接触（入力）」から「現在のツール呼び出し」までの経過時間を基準に通知を制御する。

1.  **セッションタイマーの管理**:
    - **初期化/リセット**: `BeforeAgent` および `AfterTool` (ask_user) 実行時に、ロックファイルへ現在時刻を `Atomic` に書き込む。
    - **経過時間の定義**: `現在時刻 - ロックファイルの時刻`。
2.  **待機通知のトリガー**:
    - `BeforeTool` (ask_user) 実行時に経過時間を計算。
    - `経過時間 >= JINTRICK_TOAST_THRESHOLD_MS`（デフォルト 30s）の場合にのみ通知を実行。
3.  **完了通知の最適化**:
    - `AfterAgent` 実行時も同様の経過時間判定を行い、直前にユーザーが操作していた場合は通知をスキップする。

## 実装内容詳細

### 1. 聖典の遵守 (Strict Compliance)
実装にあたっては、必ず `docs/reference/hooks-spec.md` を参照せよ。
特に以下のマジックストリングとデータ構造を正確に使用すること：
- イベント名: `BeforeTool`, `AfterTool`, `BeforeAgent`, `AfterAgent`
- キー名: `hook_event_name`, `tool_name`, `decision`, `systemMessage`
- 戻り値: 常に `exit(0)` で `{"decision": "allow"}` を返す（通知は副作用として実行）。

### 2. `hooks/hooks.json` の更新
`ask_user` ツールを監視対象に追加する。
```json
{
  "matcher": "ask_user",
  "hooks": [
    {
      "name": "toast-notification-ask-user",
      "type": "command",
      "command": "node \"${extensionPath}${/}dist${/}hooks${/}toast_notification_hook.cjs\""
    }
  ]
}
```
※ `BeforeTool` および `AfterTool` の両方に配置すること。

### 3. `toast_notification_hook.cjs` のロジック拡張
- **`BeforeTool` (ask_user)**: 経過時間をチェック。閾値を超えていれば `showToast` を実行。タイトルは `Gemini CLI: 入力待ち` とする。
- **`AfterTool` (ask_user)**: ロックファイルを現在時刻で更新（ユーザーが回答した＝接触したと見なす）。
- **`AfterAgent`**: 経過時間をチェック。閾値を超えていれば完了通知を送信。

## 受入基準 (Acceptance Criteria)
- [ ] エージェントが 30 秒（閾値）以上思考した後に `ask_user` を呼び出した際、トースト通知が表示される。
- [ ] ユーザーが `ask_user` に回答してから 30 秒以内にタスクが完了（AfterAgent）した場合、完了通知は送信されない（二重通知の防止）。
- [ ] `/settings` で `Toast Threshold (ms)` を変更し、再インストール（環境変数の反映）した際、新しい閾値で動作する。
- [ ] 全てのフック実行において、エージェントの動作を妨げない（常に `decision: allow` を返す）。
