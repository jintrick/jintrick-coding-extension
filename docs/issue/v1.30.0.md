# Issue: esbuild の並列化と実行オーバーラップによるビルド高速化

## 概要
`tools/build.cjs` において、`esbuild.build` を Promise 配列として一括発行し、その待機時間中に同期的な `promoteKnowledge` 処理を実行することで、全体のビルド時間を短縮する。

## 背景と問題点
現在の `build()` 関数は `for...of` ループ内で各 `esbuild.build` を `await` しており、並列実行可能なタスクを順次実行している。また、`promoteKnowledge` が開始されるのは全ての esbuild タスクが完了した後であり、IO 待ち時間を有効活用できていない。

## 解決策
1. **esbuild の並列発行**: `hooks` および `linters` の `esbuild.build` 呼び出しを `Promise` 配列に格納し、`Promise.all` で一括管理する。
2. **実行フェーズのオーバーラップ**: `esbuild` タスクの発行直後（`await` する前）に、同期的な `promoteKnowledge()` 処理を開始する。
3. **一括完了待機**: `promoteKnowledge()` の終了後、`Promise.all` を `await` して全 esbuild タスクの完了を保証する。

## 実装内容詳細

### 1. tools/build.cjs のリファクタリング
- `build()` 関数内の `hooks` ループと `linters` ループにおいて、`await` を削除し、戻り値の Promise を一つの配列（例: `const tasks = []`）に `push` する。
- 各 Promise 生成時に、成否を判別できるよう以下のログ出力を追加する：
  - 開始時: `console.log(\`[build:esbuild] Starting: \${hook}\`)` (または `linter`)
  - 完了時: `.then(() => console.log(\`[build:esbuild] Finished: \${hook}\`))`
- `promoteKnowledge()` を呼び出す。この際、`await` は不要（同期的実行のため）。
- 最後に `await Promise.all(tasks)` を実行し、全タスクの完了を待機する。

### 2. エラーハンドリング
- `Promise.all(tasks).catch(...)` により、いずれかのビルドが失敗した場合は `process.exit(1)` で異常終了させる。不完全な成果物で「Success」を出力してはならない。

- [ ] `npm run build` がエラーなく完了すること。
- [ ] `dist/hooks/` および `dist/skills/` に正しい成果物が生成されていること。
- [ ] ログに `[build:esbuild] Starting/Finished` が並列（入り混じった状態）で出力されていること。
- [ ] 意図的にエラーを起こした際（不正なJSファイル等）、ビルドプロセス全体が Exit Code 1 で終了すること。

## 禁止事項と代替行動
| 禁止事項 | 代替行動 |
| :--- | :--- |
| `fs.promises` への移行 | 既存の `fs.*Sync` メソッドを維持する。 |
| `promoteKnowledge` の非同期化 | 同期処理のまま維持し、esbuild の背後で実行させる。 |
| ログ出力のプレフィックス省略 | 指定された `[build:esbuild]` プレフィックスを必ず使用する。 |
