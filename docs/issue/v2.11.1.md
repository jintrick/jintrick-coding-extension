# Issue: single_edit_per_turn_hook の正常化と規約遵守（replaceツール限定・一時ファイル場所の修正）

## 背景と問題点
現在、同一ターン内での重複編集を防止する `single_edit_per_turn_hook.cjs` には、以下の設計・実装上の致命的な欠陥がある。

1. **プロジェクト規約違反**: ロックファイルを `hooks/cache/` というプロジェクトディレクトリ内に作成しており、`no-temp-files-in-root.md` 規約に違反している。
2. **過剰な制限**: 内容を一括上書きする `write_file` までブロック対象に含まれており、副作用がない操作まで妨げている。本来、不整合が問題となるのは外科的編集を行う `replace` ツールのみである。
3. **リセットの脆弱性**: ターン終了時 (`AfterAgent`) のクリーンアップに依存しており、中断時にロックが残留して次ターン以降の編集を永久に阻害するリスクがある。

## 解決策
フックの実装を「不整合の防止」という本来の目的に純化し、かつプロジェクト規約を遵守する形に修正する。

1. **対象の限定**: 監視対象を `replace` ツールのみに限定する。
2. **規約遵守 (一時ディレクトリの使用)**: ロックファイルの保存先をプロジェクト内ではなく、OS標準の一時ディレクトリ（`os.tmpdir()`）に変更する。
3. **堅牢なリセット**: ターン開始時 (`BeforeAgent`) に必ずロックを初期化（前回の残存ファイルを削除）するロジックに変更し、ブロックの永続化を根絶する。

## 実装内容詳細
- `hooks/scripts/single_edit_per_turn_hook.cjs` の修正 (一時ディレクトリ使用、replace限定、BeforeAgentリセット追加)
- `hooks/scripts/toast_notification_hook.cjs` の修正 (規約遵守のため一時ディレクトリ使用に変更)
- `hooks/hooks.json` のマッチャーおよびイベント設定の更新
- ロックファイル生成ロジックの修正（`os.tmpdir()` の活用）
