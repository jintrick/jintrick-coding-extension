# Issue: Compressed Instruction (圧縮命令) 概念の聖典統合

## 概要
`prompt_crafter` スキルの設計原則（agent-document-spec.md）に「Compressed Instruction（圧縮命令）」の概念を導入し、エージェントが「高密度・一意・高シグナル」な指示を設計・評価できる能力を確立する。

## 背景と問題点
現在の聖典（agent-document-spec.md）は「抽象語の排除」というネガティブな制約（～してはならない）に偏っており、指示の密度を積極的に高めるポジティブな設計手法が定義されていない。
その結果、指示が冗長になりやすく、コンテキストウィンドウの浪費やエージェントの挙動の揺れを招いている。

## 解決策
「Compressed Instruction（圧縮命令）」という概念を聖典の柱の一つとして追加する。
これは、特定の文脈、制約、動作原理を一語にパッケージ化し、解釈の余地を排除した「高密度な命令語」を用いる設計手法である。

例:
- `Atomic`: 1つの操作で1つの変更のみを行う（不可分性）。
- `Idempotent`: 何回実行しても同じ結果になる（べき等性）。
- `High-signal`: 意味のない冗長な表現を排除し、情報密度を最大化する。

## 実装内容詳細
1. **`skills/prompt_crafter/references/agent-document-spec.md` の更新**:
   - 新セクション「Compressed Instruction (圧縮命令)」の追加。
   - 概念の定義（高密度パッケージ化、一意性の担保）。
   - 具体的な推奨語彙（Atomic, Idempotent, High-signal等）の例示と、それらが「どのような文脈を圧縮しているか」の解説。

2. **`skills/prompt_crafter/SKILL.md` の更新**:
   - 任務と動作（品質レビュー）において、提案されたプロンプトが「圧縮命令」を適切に活用しているかを評価基準に加える。

## ゴール
- `agent-document-spec.md` に「Compressed Instruction」のセクションが存在し、その定義と活用法が明文化されている。
- `prompt_crafter` スキルを用いたレビューにおいて、指示の冗長性が指摘され、適切な「圧縮命令」への置換が提案される。
- `npm test` がパスする（既存テストの整合性確認）。
