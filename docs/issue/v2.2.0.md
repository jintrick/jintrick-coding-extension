# Issue: テスト実行時のビルド競合回避とビルドスクリプトの堅牢化

## 概要
`npm test` (vitest) 実行時に複数のテストが並列で `tools/build.cjs` を実行することで発生する、`dist/` ディレクトリの破壊的競合を解消する。また、不完全なナレッジディレクトリによるビルド中断を防止し、テスト環境の安定性を向上させる。

## 背景と問題点
1. **Race Condition**: `tools/build.cjs` は実行開始時に `dist/hooks` を削除する。Vitest がテストを並列実行するため、あるテストがビルドした成果物を、別のテストのビルド開始処理が削除してしまい、`ENOENT` エラーを引き起こしている。
2. **Brittle Build**: `knowledge/` 内に `detector.json` がないディレクトリが存在すると、ビルドスクリプトが例外を投げて停止する。テストコードが一時的に作成するディレクトリにより、ビルド全体が失敗し、テスト環境が壊れる原因となっている。

## 解決策
1. **非破壊ビルドモードの導入**: `tools/build.cjs` に環境変数（例: `SKIP_CLEANUP=1`）によるクリーンアップスキップ機能を追加する。
2. **テストコードの修正**: ビルドを伴うテストにおいて、不要なクリーンアップを避ける設定でビルドを実行するように変更する。
3. **ビルドスクリプトの例外処理緩和**: `detector.json` 等が見つからないナレッジディレクトリをエラー（throw）ではなく、警告（warn）を出してスキップするように変更する。
4. **テストの実行制御**: ビルド競合が激しいテストファイルについては、Vitest の設定で順次実行を検討する。

## 実装内容詳細
- `tools/build.cjs`:
    - `process.env.SKIP_CLEANUP` が真の場合、`dist/hooks` の削除をスキップする。
    - `promoteKnowledge` 関数内で、`detectors` が空の場合に `throw` せず `continue` するように修正。
- `tests/detector_json.test.js`, `tests/build_catalog.test.js`:
    - ビルド実行時に環境変数を付与するか、テスト用の独立した一時ディレクトリを使用するように調整。

## ゴール
- `npm test` が並列実行環境においても安定してパスすること。
- 不完全なナレッジディレクトリが存在しても、他の正常なコンポーネントのビルドが完了すること。
- `dist/hooks` がテストの途中で消失しないこと。
