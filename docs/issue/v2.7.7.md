# Issue: jintrick_to_system.cjs のソースパス自動解決の改善

## 背景と問題点
`tools/jintrick_to_system.cjs` のソースパス (`sourcePath`) が `v0.35.3/jintrick.md` という特定の Gemini CLI バージョンのディレクトリにハードコードされている。
Gemini CLI のアップデートにより `system_prompts/` 内に新しいバージョン（例：`v0.36.0`）のディレクトリが追加された際、スクリプトを毎回手動で書き換えない限り、古いバージョンの `jintrick.md` が `.gemini/system.md` に同期され続ける不整合が発生する。

## 解決策
`tools/jintrick_to_system.cjs` を修正し、`system_prompts/` ディレクトリ配下をスキャンして最新（セマンティックバージョニング的に最大値）のディレクトリを自動的に特定し、その配下の `jintrick.md` を同期ソースとして動的に選択するように変更する。

## 実装内容詳細

### 1. `getLatestSourcePath` 関数の定義
以下のロジックを持つヘルパー関数を `tools/jintrick_to_system.cjs` に追加する。

- **対象ディレクトリ**: `skills/gemini-cli-expert/references/system_prompts/`
- **ディレクトリ抽出**: `fs.readdirSync` を使用し、`vX.Y.Z` 形式（例：`v0.35.3`）のディレクトリ名のみを抽出する。
- **バージョンソート**:
  - `v` 接頭辞を除去し、`.` で分割して整数配列 `[major, minor, patch]` に変換する。
  - 数値として比較を行い、最新のバージョンを特定する（`Intl.Collator` の `numeric: true` も検討可だが、堅牢性のために数値分割比較を推奨）。
- **パス構築**: 最新バージョンのディレクトリ内の `jintrick.md` への絶対パスを生成する。

### 2. エラーハンドリングの強化
- バージョン形式のディレクトリが 1 つも見つからない場合、「No version directories (vX.Y.Z) found」というエラーメッセージを出力し、プロセスを `1` で終了する。
- 最新バージョンのディレクトリ内に `jintrick.md` が存在しない場合、「jintrick.md not found in the latest version directory」というエラーメッセージを出力し、プロセスを `1` で終了する。

### 3. CLI 実行ロジックの更新
- `require.main === module` ブロック内で `getLatestSourcePath()` を呼び出し、動的に `sourcePath` を取得する。
- 実行時に「Sanitizing and generating .gemini/system.md from [決定されたパス] ...」と表示し、どのソースが使用されたかを確認可能にする。

## ゴール
- スクリプトの手動更新なしに、常に最新のシステムプロンプト（`jintrick.md`）が `.gemini/system.md` に反映される。
- バージョン不整合による古いプロンプトの使用を完全に排除する。
- ソースが見つからない場合に、原因が即座に特定できるエラーログが出力される。

## テスト

**テスト対象 1: 自動バージョン選択ロジック (`getLatestSourcePath` 関数の単体テスト)**
- **テスト内容**: 複数のバージョン名ディレクトリ (`vX.Y.Z`) から、セマンティックバージョニングの最大値を正しく特定できるか。
- **検証方法**: モックを用いた自動テスト (`npm test tests/jintrick_to_system.test.js`)。
  - ケース1: `v0.35.3` と `v0.36.0` から `v0.36.0` を選択する。
  - ケース2: `v0.35.3`, `v1.10.0`, `v2.0.0`, `v1.2.0` から `v2.0.0` を選択する。

**テスト対象 2: システムプロンプト生成プロセスの結合テスト（実機動作）**
- **テスト内容**: スクリプト全体を実行した際、ハードコードされたパスではなく、最新バージョンのディレクトリからファイルを読み取り、`.gemini/system.md` を正しく生成・上書きできるか。
- **検証方法**: 手動での実機検証 (`node tools/jintrick_to_system.cjs`)。
  - 手順1: `v0.36.0/jintrick.md` を一時的に作成し、スクリプトを実行する。
  - 手順2: コンソールのログ出力に `v0.36.0` のパスが表示されることを確認する。
  - 手順3: 生成された `.gemini/system.md` の内容が `v0.36.0` のものと一致するか確認する。

## Appendix: 技術的選定理由 (Why/Why Not)
- **SemVerライブラリの不使用**: `semver` などの外部パッケージを導入することも考えられたが、CLI の内部依存関係を増やさないため、またディレクトリ名 (`vX.Y.Z`) の構造が明確であるため、文字列を分割して数値比較する軽量なロジックを実装する選択をした。
