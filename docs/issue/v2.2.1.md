# Issue: ビルドスクリプトのモジュール化とテスト並列化の完全対応

## 概要
`v2.2.0` で導入された `SKIP_CLEANUP` 環境変数と `vitest` の直列実行（`fileParallelism: false`）を廃止する。`tools/build.cjs` を関数としてモジュール化し、出力先ディレクトリを動的に指定可能にすることで、テスト実行時のリソース競合（`ENOENT`, `EBUSY`）を根本的に解消し、テストの並列実行を再有効化する。

## 背景と問題点
1. **テスト実行の非効率性**: `vitest.config.js` で `fileParallelism: false` を指定しているため、テストが直列に実行され、CI の実行時間が不必要に長くなっている。
2. **場当たり的な競合回避**: `SKIP_CLEANUP` は `dist/` の削除を回避するだけであり、同一ディレクトリへの同時書き込みによる Race Condition は解消されていない。
3. **検証強度の低下**: `v2.2.0` では不完全なナレッジディレクトリに対して `console.warn` で妥協したが、これは将来的に不正な成果物が生成されるリスクを許容してしまっている。

## 解決策
1. **`tools/build.cjs` のリファクタリング**: 
   - 全体のビルド処理を `async function build(options)` に、ナレッジ昇格処理を `function promoteKnowledge(options)` にカプセル化する。
   - `options` にて `distDir`, `knowledgeDir`, `skillsDir`, `clean`, `version` を指定可能にする。
   - `module.exports` による関数エクスポートを追加する。
   - `require.main === module` の場合のみ、デフォルト引数で `build()` を実行する互換性を維持する。
2. **検証ロジックの厳格化**: `promoteKnowledge` 内で detector が生成できない場合の挙動を `throw Error` に戻す。
3. **テストコードの隔離**:
   - `tests/build_catalog.test.js` および `tests/detector_json.test.js` において、`execSync('node tools/build.cjs')` を廃止し、モジュール化された関数を直接呼び出す。
   - 各テストスイートごとにユニークな一時ディレクトリ（`tests/tmp/v2.2.1/build` 等）を使用し、完全に隔離された環境で検証を行う。
4. **並列実行の再有効化**: `vitest.config.js` を更新（または削除）し、`fileParallelism: true` を有効にする。

## 実装内容詳細

### 1. `tools/build.cjs` の変更
- `promoteKnowledge` の引数を `({ knowledgeDir, skillsDir, extensionVersion, clean = true })` とし、内部の `knowledge`, `skills` という文字列を引数に基づいた変数に置き換える。
- `build` の引数を `({ distDir, knowledgeDir, skillsDir, clean = true })` とし、`dist`, `knowledge`, `skills` のパスを動的に解決する。
- `esbuild` の `outfile` パス生成ロジックを `distDir` 基点に変更する。
- detector 生成失敗時の `console.warn` を `throw new Error(...)` に戻す。

### 2. `tests/build_catalog.test.js` の変更
- `import { promoteKnowledge } from '../tools/build.cjs'` を使用する。
- `beforeEach` で `tests/tmp/catalog/knowledge` 等の独立したパスを構築する。
- `promoteKnowledge` を直接実行し、アサーションを行う。

### 3. `tests/detector_json.test.js` の変更
- `import { promoteKnowledge } from '../tools/build.cjs'` を使用する。
- `tests/tmp/detector/knowledge` 等の独立したパスを構築する。
- `promoteKnowledge` を直接実行し、アサーションを行う。
- `throw Error` が発生することを `expect(...).toThrow()` で検証する。

### 4. `vitest.config.js` の変更
- `fileParallelism: true` に変更、またはデフォルトに戻すためにファイルを削除する。
