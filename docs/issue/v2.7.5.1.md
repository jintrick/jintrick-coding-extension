# Issue: single_edit_per_turn_hook におけるキャッシュファイルのクリーンアップ不全およびブロックの永続化の修正

## 背景と問題点
Issue v2.7.5 で導入された `single_edit_per_turn_hook.cjs` において、以下の不具合が確認された。

1.  **パス解決の不整合**: 実行時に `__dirname` が `dist/hooks/` を指すため、キャッシュが `dist/cache/` に生成されるが、ビルドツールやテスト環境との整合性が取れていない（本来は `hooks/cache/` を期待）。
2.  **クリーンアップの失敗**: `AfterAgent` イベント時に `session_id` が期待通りに渡されない、あるいはパス計算が食い違うことで、`modified_${session_id}.json` が削除されずに残存する。
3.  **ブロックの永続化**: クリーンアップに失敗したファイルが残っていると、次のターン以降で `BeforeTool` がそれを検知し続け、同一ファイルの編集が永久にブロックされる。

## 解決策
1.  **パス解決の正規化**: キャッシュディレクトリを `path.resolve(__dirname, '..', '..', 'hooks', 'cache')` を用いて、拡張機能ルートの `hooks/cache/` に固定する。これにより、ソース（開発時）とビルド成果物（実行時）の両方で同一のディレクトリを参照する。
2.  **セルフヒーリングの実装**: `BeforeTool` 実行時に、キャッシュファイルの最終更新時刻を確認し、一定時間（5分）以上経過している場合は、前のターンが異常終了したものとみなして強制的に削除するロジックを追加する。
3.  **堅牢なクリーンアップ**: `AfterAgent` 時に `session_id` が取得できない場合やファイル削除に失敗した場合でも、安全に `allow` を返すようにガードを強化する。

## 実装内容詳細

### 1. Hook スクリプトの修正 (`hooks/scripts/single_edit_per_turn_hook.cjs`)
- **パス正規化**:
  `cacheDir` を `path.resolve(__dirname, '..', '..', 'hooks', 'cache')` に変更。
- **BeforeTool ロジックの拡張**:
  `modified_${session_id}.json` が存在する場合、`fs.statSync(cacheFile).mtimeMs` を取得し、`Date.now()` との差分が 300,000ms (5分) を超えていれば削除してから処理を開始する。
- **AfterAgent ロジックの堅牢化**:
  `session_id` の存在確認を強化し、`fs.unlinkSync` を `try-catch` ブロックで保護する。

### 2. テストコードの修正 (`tests/hooks/single_edit_per_turn_hook.test.js`)
- **古いキャッシュの自動削除テスト**:
  `fs.utimesSync` を用いて 5 分以上前のタイムスタンプを持つ擬似キャッシュファイルを作成し、`BeforeTool` 呼び出し時にそれが削除され、新規編集が `allow` されることを検証するテストケースを追加する。

## ゴール
- ターンの終了時にキャッシュが確実に削除されること。
- 万が一残存した場合でも、次のターン（5分後以降）には自動的に解消され、編集がブロックされないこと。
- 実行環境に関わらず `hooks/cache/` ディレクトリが一貫して使用されること。
