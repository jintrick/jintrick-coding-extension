# Issue: ナレッジ検知用メタデータの標準化（detector.json の導入）

## 概要
`knowledge/` 配下の各技術スタックにおいて、プロジェクト検知用のヒントとして `package.json` を流用していた設計を廃止し、専用の `detector.json` を導入する。これにより、npm エコシステムとの競合を解消し、非 JS 環境を含む多言語スタックへの対応を強化する。

## 背景と問題点
- **npm との競合**: `knowledge/` 内に `package.json` が存在すると、npm が独立したパッケージと誤認し、不要な `node_modules` 生成や依存関係の混乱を招く。
- **意味の混同**: 「ナレッジ自体のメタデータ」と「対象プロジェクトの検知条件」が同一ファイルに混在しており、拡張性が乏しい。
- **非JS環境への対応**: Python や Go などの技術スタックにおいても `package.json` を置くのは不自然であり、統一的な検知プロトコルが必要である。

## 解決策
- `package.json` による検知ロジックを廃止し、`detector.json` を正とする。
- `tools/build.cjs` において `detector.json` を優先的に読み込み、`manifest.json` の `detectors` フィールドを生成する。
- 既存の推論ロジック（`requirements.txt` 等）は後方互換性のために維持するが、`detector.json` が存在する場合はそれを優先する。

## 実装内容詳細

### 1. `detector.json` のスキーマ定義
各 `knowledge/<stack>/` 配下に配置される `detector.json` は以下の形式とする（すべて任意項目）。

```json
{
  "npm": "string",          // package.json の name フィールドを指定。生成時: { "type": "file_contains", "file": "package.json", "pattern": "\"<npm>\"" }
  "files": ["string"],      // 存在を確認するファイルリスト。生成時: { "type": "file_exists", "file": "<item>" }
  "patterns": [             // ファイル内の特定パターンを検知。
    {
      "file": "string",
      "pattern": "string"
    }
  ]
}
```

### 2. `tools/build.cjs` の修正
`promoteKnowledge` 関数内の `detectors` 生成ロジックを以下のように変更する。

- **`detector.json` の処理**:
  - `knowledge/<stack>/detector.json` が存在するか確認。
  - 存在する場合、`fs.readFileSync` で読み込み、`JSON.parse` を実行。
  - **エッジケース対応**:
    - `JSON.parse` が失敗（ファイル破損や不正なJSON）した場合は、`console.error` で警告を出力し、そのスタックの `detector.json` 処理をスキップして既存の推論ロジックへフォールバックする。
    - 各フィールド（`npm`, `files`, `patterns`）の型チェックを行い、期待されない型の場合は無視する。
  - パースに成功したデータを `manifest.json` の `detectors` 形式に変換して配列に追加する。
- **既存推論ロジックの優先順位**:
  1. `detector.json` が存在し、有効なエントリがある場合はそれを使用し、以降の推論（`package.json` スキャン等）をスキップする。
  2. `detector.json` が存在しない場合は、従来の `package.json`, `requirements.txt`, `pyproject.toml`, `*.config.js` 等のスキャンを実行する。

### 3. ドキュメントの更新
- `docs/reference/tech-expert-spec.md` の「3. プラグアンドプレイ・モジュールの仕様」セクションを更新し、`detector.json` を推奨される検知方法として明記する。

### 4. 既存ナレッジの移行
- 現在 `knowledge/` 配下に `package.json` が存在する場合、それを `detector.json` へ移行（リネームおよびフォーマット変換）し、元の `package.json` を削除する。

## 影響範囲
- `tools/build.cjs`: ビルドロジックの変更。
- `knowledge/`: メタデータファイルの配置変更。
- `docs/reference/tech-expert-spec.md`: 仕様ドキュメントの更新。

## テスト計画

### 1. ユニットテストの追加
`tests/build_catalog.test.js` に以下のテストケースを追加する。
- `detector.json` が存在する場合、正しく `manifest.json` に反映されること。
- `detector.json` が破損（不正なJSON）している場合、ビルドが中断されず、警告が表示された上で従来の推論が行われること。
- `npm`, `files`, `patterns` の各フィールドが正しく変換されること。

### 2. 手動検証
1. `knowledge/test-stack/detector.json` を作成し、`npm run build` を実行。
2. `dist/skills/tech-expert-test-stack/manifest.json` の `detectors` 内容を目視確認。
