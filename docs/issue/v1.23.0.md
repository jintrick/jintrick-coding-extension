# Issue: v1.23.0 - Unified Tech-Expert Agent with Plug-and-Play RAG Architecture

## 概要
複数の技術スタックを統合的に扱う専門サブエージェント `tech-expert` を導入する。各技術スタックの RAG 知識をプラグアンドプレイ可能なモジュールとして構成し、`SessionStart` フックによる自動検知と `.gemini/tech-discovery.md` の動的更新を通じて、メインエージェントに「専門家の利用」を絶対的命令として自律的に周知・強制するシステムを構築する。

## 背景と問題点
- 技術スタック（React, MUI, CP-SAT 等）ごとに個別のサブエージェントを定義すると、管理が煩雑になりエージェントが乱立する。
- 統合エージェントを作っても、メインエージェントに対して「このプロジェクトではこの専門家を使え」という強制的な命令（Foundational Mandate）を与えない限り、自律的な利用は期待できない。
- 新しい技術スタック（知識ベース）を追加するたびに、フックのコードやエージェントのプロンプトを手動で修正するのはスケーラビリティに欠ける。

## 解決策
1. **完全プラグアンドプレイ型 RAG**: 
   `skills/tech-expert-*/` というプレフィックスを持たせた第一階層ディレクトリとして各技術スタック（モジュール）を配置する。各ディレクトリ内の `manifest.json`（検知条件）により、フォルダを追加するだけで新しい技術が自動認識される。
2. **`SessionStart` フックによる初期周知**:
   `SessionStart` フックがプロジェクトをスキャンし、検知された技術スタックのリストと `tech-expert` の利用指示を、`systemMessage` (ユーザー向け) および `additionalContext` (エージェントの初期コンテキスト) として注入する。
3. **動的スキル・アクティベーション**:
   `tech-expert` サブエージェントは、起動時に自身でマニフェストをスキャンし、ユーザーの質問に最適な技術のスキル（例：`tech-expert-react`）を `activate_skill` でオンデマンドにロードする。

## 実装内容詳細

### 1. サブエージェント定義 (`agents/tech-expert.md`)
- `activate_skill`, `list_directory`, `read_file`, `grep_search` をツールとして持つ。
- 自身のプロンプト内に特定の技術名をハードコードしない。
- 起動時、`skills/tech-expert-*/manifest.json` を自律的に読み込み、利用可能な技術カタログを構築した上で、最適なスキルをロードするよう指示する。

### 2. プラグアンドプレイの仕組み (`skills/tech-expert-*`)
- 例として `skills/tech-expert-react/` ディレクトリを作成し、以下の構造を持たせる。
  - `manifest.json` (例: `{"id": "react", "detectors": [{"file": "package.json", "contains": "\"react\""}]}`)
  - `SKILL.md` (React専門家としての指示とRAGロード手順。フロントマターの `name` は `tech-expert-react` とする)
  - `references/` (ドキュメント群)

### 3. 検知とコンテキスト注入フック (`hooks/scripts/tech_stack_discovery_hook.cjs`)
- `SessionStart` イベントで発火。
- `skills/` 内の `tech-expert-` で始まるディレクトリの `manifest.json` をすべて読み込み、プロジェクトディレクトリと照合する。
- 検知された技術がある場合、`hookSpecificOutput.additionalContext` を使用して、エージェントの履歴の最初のターンとして以下の指示を注入する。
  > [SYSTEM] このプロジェクトでは以下の技術が検出されました: [React, MUI]
  > これらに関するアーキテクチャ、実装、エラー解決の質問は、必ず `tech-expert` サブエージェントに委ねよ。
- 同時に `systemMessage` でユーザーのターミナルにも検知結果を通知する。

### 4. マニフェスト更新
- `gemini-extension.json` に新設したフック (`SessionStart` 用) とエージェント (`tech-expert`) を登録する。

## ゴール
- [ ] スキルディレクトリを追加するだけで、フックやプロンプトの修正なしに新しい技術がシステムに認識されること。
- [ ] `SessionStart` フックがプロジェクトを正しく検知し、初期コンテキストとしてエージェントに周知できること。
- [ ] `tech-expert` サブエージェントが、質問に応じて適切な `SKILL.md` をロードできること。
- [ ] メインエージェントが初期コンテキストの指示を尊重し、対象技術について `tech-expert` を自律的に呼び出すこと。
