# Issue: プロジェクト構成同期フックにおける一時ディレクトリの完全サイレント化と通知の義務化

## 背景と問題点
`v2.17.0` で導入された `project_template_sync_hook.cjs` は、Gemini CLI が内部管理用に生成する一時作業ディレクトリ（`.gemini/tmp` 配下等）に対しても実行されている。これにより、一時ディレクトリにおいて不要な同期処理が走り、「同期をスキップしました」といったノイズとなる通知がユーザーに表示される問題がある。一時ディレクトリでの実行は完全に無視（サイレント化）すべきである。

一方で、正規のワークスペース（プロジェクトルート等）で実行された際、ファイルが既に最新で更新が発生しなかった場合に何も通知されないと、同期機能が正常に動作しているか不安を与える。正規の実行コンテキストでは、状態にかかわらず明示的な通知を行うべきである。

## 解決策
- **一時ディレクトリの完全サイレント化**: `process.cwd()` をチェックし、パスに `.gemini/tmp` が含まれる場合は、`systemMessage` を含めずに即座に終了するガード節を導入する。
- **通知の義務化**: 正規のプロジェクトディレクトリにおいて、更新ファイルが 0 件の場合でも「jintrick 標準構成は最新の状態です」と通知するようロジックを修正する。
- **通知メッセージの統一**: 更新があった場合の通知メッセージを、具体件数を含めた形式に改善する。

## 規約準拠 (Rule Compliance)
- **comment-preservation.md**:
  - パス判定のガード節において、なぜそのパスを無視するのか（CLIの内部挙動との関連）を解説するコメントを付与し、将来のメンテナンス時に意図が伝わるようにする。
- **no-temp-files-in-root.md**:
  - パス判定や状態チェックの過程で、ディスク上に一時的なフラグファイル等を作成しないこと。

## 実装手順
1. **一時ディレクトリ判定ロジックの実装**:
   - `hooks/scripts/project_template_sync_hook.cjs` のメイン処理の最上段で `process.cwd()` を取得する。
   - 正規表現 `/[\\/]\.gemini[\\/]tmp[\\/]/` を用いて、パスに `.gemini/tmp` が含まれているか判定する。
   - 一致した場合は、`systemMessage` を**含めない** `{ decision: 'allow' }` を直ちに返す。
2. **通知ロジックの修正**:
   - 正規のプロジェクト（`package.json` または `.git` が存在）判定後の処理を修正。
   - 更新件数 `updatedCount` が 0 の場合: `systemMessage: 'jintrick 標準構成は最新の状態です'` を戻り値に含める。
   - 更新件数 `updatedCount` が 1 以上の場合: `systemMessage: \`jintrick 標準構成のファイルを同期・更新しました（${updatedCount}件）\`` を戻り値に含める。
3. **非プロジェクト通知の維持**:
   - `package.json` も `.git` も存在しない「非プロジェクト」ディレクトリでの実行時は、従来通り `systemMessage: 'jintrick プロジェクトではないため、jintrick 標準構成の同期をスキップしました'` を返してユーザーに注意を促す。
4. **テストコードの更新**:
   - `tests/hooks/project_template_sync_hook.test.js` に以下のテストケースを追加・更新する。
     - 一時ディレクトリパス模擬時: `systemMessage` が `undefined` であることの検証。
     - 正規プロジェクトで更新 0 件時: `systemMessage` が「最新の状態です」であることの検証。
     - 正規プロジェクトで更新あり時: メッセージに更新件数が含まれていることの検証。
