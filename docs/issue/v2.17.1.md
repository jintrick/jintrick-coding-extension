# Issue: プロジェクト構成同期フックにおける情報の源泉を stdin.cwd に完全一本化し、一時ディレクトリを徹底排除する

## 背景と問題点
`v2.17.0` で導入された `project_template_sync_hook.cjs` において、通知の重複や誤動作が発生している。
原因は、フックが「どのディレクトリを処理すべきか」の判断において、Gemini CLI から明示的に渡される `stdin.cwd` ではなく、Node.js プロセスのカレントディレクトリ（`process.cwd()`）に依存していることにある。

CLI が一時ディレクトリ（`.gemini/tmp` 配下）を対象としてフックを起動しても、フックプロセス自体の `process.cwd()` がメインプロジェクトを指している場合、一時ディレクトリ用のガードを突き抜けてメインプロジェクトに対して不必要な同期処理と通知を実行してしまう。これは情報の源泉が不純であることに起因する致命的な設計不備である。

## 解決策（厳格な要件）
1.  **情報の源泉の純粋化**: 
    - `process.cwd()` の使用を全面的に廃止し、削除する。
    - 標準入力（stdin）から渡される JSON オブジェクト内の `cwd` プロパティを、**唯一の絶対的なソース**として使用する。
2.  **一時ディレクトリの完全排除**:
    - `cwd` プロパティが一時ディレクトリ（パスに `.gemini/tmp` を含む等）を指している場合、一切の猶予なく直ちに終了（Ignore）し、何も出力しない。
3.  **メッセージの義務化**:
    - 正常なワークスペース（`cwd` プロパティが指す場所）において、更新が 0 件であっても必ず「jintrick 標準構成は最新の状態です」と通知する。

## 設計上の考慮点 (Rule Compliance)
- **comment-preservation.md**:
  - `process.cwd()` を廃止し、`stdin.cwd` に一本化した理由（CLI の指定を絶対視するため）をコード内に明記し、文脈を保護せよ。
- **no-temp-files-in-root.md**:
  - 同期処理および判定において、ファイルシステム上に一時ファイルを作成してはならない。

## 実装手順
1.  **入力データの解析**:
    - `hooks/scripts/project_template_sync_hook.cjs` にて、`JSON.parse(fs.readFileSync(0, 'utf-8'))` により入力を取得する。
2.  **絶対的ソースの定義**:
    - 取得したオブジェクトから `cwd` プロパティを抽出し、変数 `targetCwd` に格納する。これ以降、`process.cwd()` は一切使用しない。
3.  **一時ディレクトリガードの修正**:
    - `targetCwd` のパス文字列に `[\\/]\.gemini[\\/]tmp[\\/]` が含まれるかを検証する。
    - 含まれる場合は、直ちに `{ decision: "allow" }` を出力してプロセスを終了する。
4.  **同期先パスの修正**:
    - `package.json` や `.git` の存在確認、および `copyDirWithMtimeCheck` の第 2 引数（コピー先）をすべて `targetCwd` ベースに書き換える。
5.  **通知ロジックの確定**:
    - 同期の結果 `updatedCount === 0` であっても、正常なワークスペースであれば必ず `systemMessage: "jintrick 標準構成は最新の状態です"` を含めて応答する。
