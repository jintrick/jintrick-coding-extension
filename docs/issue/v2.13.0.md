# Issue: `coding-rules` スキルの実装と各エージェントへの統合

## 背景と問題点
現在、コーディングルールの注入はファイル変更直前のHook (`coding_rules_hook.cjs`) で行われている。これはコードを記述する段階では機能するが、設計 (`issue-crafter`) やレビュー (`code-reviewer`) の段階では遅すぎるため、ルールを事前に考慮した設計やレビューが行えないという問題がある。

## 解決策
- `skills/coding-rules/` に新規スキルを作成し、事前にルールを取得するためのスクリプト `get-rules.cjs` を実装する。
- `agents/issue-crafter.md` および `agents/code-reviewer.md` を更新し、設計・レビューの前に `coding-rules` スキルを活用してルールを取得・適用するように指示を追加する。

## 実装内容詳細

### 1. `skills/coding-rules/` の作成
- `SKILL.md` の作成:
  - エージェントに対し、設計やレビューの前にコーディングルールを取得することを指示する内容を記述する。
- `scripts/get-rules.cjs` の実装:
  - `.agent/rules/` ディレクトリ内のルールファイルをパースし出力する Node.js スクリプト。
  - 複数のファイルパスを標準のコマンドライン引数として受け付ける（例: `node scripts/get-rules.cjs src/a.py src/b.js`）。JSON文字列のエスケープによるエラーを防ぐため、単純な引数リストとする。
  - 処理結果は、トークン消費の重複を防ぐため **正規化されたJSON形式** で標準出力に返す。
    ```json
    {
      "rules": {
        "rule1.md": "ルールの本文...",
        "rule2.md": "ルールの本文..."
      },
      "mapping": {
        "src/a.py": ["rule1.md"],
        "src/b.js": ["rule1.md", "rule2.md"]
      }
    }
    ```
  - 引数が省略された場合は、すべてのルールを `"rules"` オブジェクトに格納して出力する。

### 2. `agents/issue-crafter.md` の更新
- 必須スキル（もしくは Required Skills）のリストに `coding-rules` を追加する。
- 設計時に `get-rules.cjs` を実行して対象ファイルに関連するルールを取得し、それをIssueの完了条件（タスクリスト）に含めるよう指示を追加する。

### 3. `agents/code-reviewer.md` の更新
- `tools` リストに `activate_skill` と `run_shell_command` を追加する。
- レビューを実行する前に `coding-rules` スキルをアクティベートし、`get-rules.cjs` を実行してプロジェクトの規約を取得し、その規約に基づいてレビューを行うよう指示を追加する。

## 規約準拠 (Rule Compliance)
- [comment-preservation.md] -> 理由なくコメントを削除しないルール。スクリプトの実装において既存のコメント処理（パース等）を破壊しないよう考慮した。
- [no-temp-files-in-root.md] -> 一時ファイルをルートに置かないルール。テスト用のディレクトリ隔離により準拠。

## ゴール
エージェントがコードの設計およびレビューを行う前に、プロジェクト固有のコーディングルール (`.agent/rules/`) をプロアクティブに取得し、コンテキストに含められるようになること。
