# Issue: v1.29.0 - Standardize Skill Discovery and Deprecate `dist/skills`

## 概要
RAG スキルの生成先を `dist/skills/` から root の `skills/` に一本化し、Gemini CLI の標準的な Auto Discovery 経由でのアクティベーションを正常化します。また、Linter Hook とは異なりポインタが存在しないスキルにおいて、意味のない `dist/` へのコピー処理を廃止し、アーキテクチャを Gemini CLI の仕様に準拠させます。

## 背景と問題点
v1.25.0 以降、ナレッジ（RAG）を `dist/skills/` に生成し、フックだけがそこを参照するという「独自の検索ロジック」を導入していました。
しかし、以下の理由によりこの設計は破綻しています：
1. **検出の不一致**: Gemini CLI の `activate_skill` ツールは root の `skills/` しか認識しないため、`dist/` にあるスキルをロードできません。
2. **パス制御の欠如**: Linter Hook は `hooks.json` でパスを制御できますが、スキルにはそれがありません。
3. **不要な隔離**: RAG データ（Markdown/JSON）を `dist/` に置くことは、実行速度の向上に寄与せず、管理を複雑にするだけでした。

## 解決策
1. **`tools/build.cjs` の抜本的修正**: 
   - ナレッジの「昇格（Promotion）」先を、root の `skills/tech-expert-*` に変更します。
   - `skills/` から `dist/skills/` への不要なコピー処理を削除します。
   - ビルド成果物である `skills/tech-expert-*` は、リポジトリに含めて配布するため、Git 管理対象とします。
2. **`hooks/scripts/tech_stack_discovery_hook.cjs` の修正**: 
   - `dist/skills/` を優先する独自の検索分岐を削除し、CLI と同じ root `skills/` のみを参照するように戻します。
3. **`dist/skills/` の廃止**: 
   - 既存の `dist/skills/` ディレクトリを削除し、混乱を排除します。

## 実装内容詳細

### 1. `tools/build.cjs` の修正
- `promoteKnowledge()` 関数内で `targetDir` を `skills/tech-expert-${stack}` に変更。
- `build()` 関数内で `copyDir('skills', 'dist/skills');` を削除。
- `dist/skills/` のクリーンアップ処理を追加。

### 2. `hooks/scripts/tech_stack_discovery_hook.cjs` の修正
- `skillsDir` を `path.join(extensionRoot, 'skills')` に固定。

### 3. `.gitignore` の整理
- `dist/skills/` の行を削除（またはコメントアウト）。
