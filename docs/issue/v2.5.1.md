# Issue: 通知システムの最終完成（音声割り込み ＋ 堅牢な完了通知）

## 概要
`v2.5.0` で判明した「Windows UI ロックによるトースト遅延」を、音声通知（Audio層）の活用により突破する。タスク完了時のトースト強化と合わせ、Gemini CLI の対話体験を最高レベルに引き上げる。

## 背景と問題点
- Gemini CLI が `ask_user` で待機している間、Windows はトーストの描画をブロックし、回答後まで遅延させる（物理的な制約）。
- 単なる視覚通知だけでは、ユーザーが画面を見ていない場合に開発が完全に停滞する。

## 解決策: 音声と視覚のハイブリッド通知
1.  **音声による「貫通」通知**:
    - `BeforeTool` (ask_user) 時に、経過時間が閾値を超えていれば `[System.Media.SystemSounds]::Asterisk.Play()` を実行。
    - 音声は UI ロックの影響を受けず即座に鳴るため、「入力が必要であること」を確実にユーザーへ伝える。
2.  **視覚による「確実な」完了通知**:
    - `AfterAgent` 時のトースト通知に `Explorer` AppID と `Priority: High` を適用。
    - タスク完了後の静止状態で、詳細な実行結果を確実に表示させる。

## 実装内容詳細
- `hooks/hooks.json` に `BeforeTool` (ask_user) を再登録。
- `toast_notification_hook.cjs` を修正。
    - `BeforeTool` 時: PowerShell で音のみを鳴らす軽量コマンドを実行。
    - `AfterAgent` 時: 強化されたトースト送信（既存の安定版ロジック）を実行。
    - 常に `spawnSync` を使用し、プロセスの生存を保証。

## 受入基準 (Acceptance Criteria)
- [ ] 30 秒以上の思考後、`ask_user` が発生した瞬間に**システム音が鳴る**こと。
- [ ] タスク完了後、**強化されたトースト**が確実に表示されること。
- [ ] `ask_user` 回答後の「ノイズ通知（遅延トースト）」が発生しないこと。
