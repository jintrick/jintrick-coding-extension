# Issue: 完了通知の堅牢化（v2.5.0 の知見に基づく強化）

## 概要
`v2.5.0` で得た検証結果に基づき、既存のタスク完了通知（`AfterAgent`）の配信品質を向上させる。不適切な `ask_user` 通知フックを削除し、リポジトリをクリーンな状態に戻す。

## 背景と問題点
- 既存の完了通知において、稀にトーストが表示されない、あるいは表示が著しく遅れる現象が報告されている。
- `v2.5.0` の試行錯誤により追加された `ask_user` フックは、回答後に通知が飛ぶという「ノイズ」を生んでおり、削除が必要。

## 解決策
1.  **ノイズの除去**: `hooks/hooks.json` から `ask_user` に関連するフック（BeforeTool/AfterTool）を完全に削除する。
2.  **配信品質の強化**: `AfterAgent` で使用する通知ロジックに、以下の「抑制回避設定」を適用する。
    - **AppID**: `Microsoft.Windows.Explorer` (信頼されたシステム ID)
    - **Priority**: `High` (優先度を上げ、OS による破棄を防ぐ)
    - **Scenario**: `default` (完了通知のため、アラームのような永続性は不要。ただし配信優先度は保つ)
3.  **プロセスの安定化**: `spawnSync` を使用し、通知の OS 登録が完了するまでプロセスの生存を保証する。

## 実装内容詳細
- `hooks/hooks.json` の `BeforeTool` / `AfterTool` から `ask_user` の定義を削除。
- `hooks/scripts/toast_notification_hook.cjs` を修正。
    - `BeforeTool` での通知ロジックを削除。
    - `AfterAgent` での `showToast` において、`Explorer` AppID と `Priority: High` を採用。
    - 不要な `Start-Process`（二重起動）を廃止し、信頼性の高い `spawnSync` に回帰。

## 受入基準 (Acceptance Criteria)
- [ ] 30 秒以上のタスク完了後、確実にトーストが表示される。
- [ ] `ask_user` 呼び出し時に、回答後の「ノイズ通知」が発生しない。
- [ ] 完了通知のタイトルにプロジェクト名、本文に実行時間が正しく含まれている。
- [ ] `npm run build` が成功し、`dist/` に反映される。
