# Issue: 同一ターン内での同一ファイルに対する複数回編集を物理的に阻止する Hook の追加

## 背景と問題点
Gemini CLI において、同一ターン（モデルの1回の回答）の中で、同一ファイルに対して複数回の `replace` または `write_file` が呼び出された場合、以下の問題が発生する。
1. **変更の消失**: 最後に実行された書き込みのみが反映され、それ以前の変更が失われる。
2. **不整合**: モデルが「すべての変更を適用した」と誤認し、実際のファイル内容とモデルの記憶に乖離が生じる。
これは CLI の原子的なファイル操作仕様に起因するが、モデルに対して「1ファイルにつき1ターン1回の編集」という制約を明示的に強制する仕組みがないため、サイレントなデータ損失のリスクがある。

## 解決策
`BeforeTool` フックを使用して、同一ターン内での編集対象ファイルパスを `hooks/cache/` に記録し、2回目以降の同一パスへのアクセスを `decision: "deny"` でブロックする。
`AfterAgent` フックにより、ターンの終了時にこの記録をリセットすることで、次のターンでは再び編集を許可する。

## 実装内容詳細

### 1. 新規 Hook スクリプトの作成 (`hooks/scripts/single_edit_per_turn_hook.cjs`)
以下のロジックを実装する。
- **BeforeTool (matcher: "write_file|replace")**:
  - `tool_input.file_path` を取得する。
  - `hooks/cache/modified_${session_id}.json` を読み込む。存在しない場合は `[]` とする。
  - 取得したパスが配列に含まれている場合、以下の JSON を出力してプロセスを終了（exit 0）する。
    ```json
    {
      "decision": "deny",
      "reason": "Duplicate file edit in a single turn",
      "systemMessage": "同一ターン内での同一ファイルに対する複数回の編集（replace/write_file）は禁止されています。すべての変更を1つの write_file にまとめるか、一旦思考を止めてユーザーに報告し、次のターンで残りの編集を行ってください。"
    }
    ```
  - 含まれていない場合、パスを配列に追加してファイルを保存し、`{"decision": "allow"}` を出力する。
- **AfterAgent (matcher: "*")**:
  - `hooks/cache/modified_${session_id}.json` を削除する。
  - `{"decision": "allow"}` を出力する。

### 2. Hook の登録 (`hooks/hooks.json`)
以下の 2 つの定義を追加する。
```json
{
  "hooks": {
    "BeforeTool": [
      {
        "matcher": "write_file|replace",
        "hooks": [
          {
            "name": "single-edit-per-turn",
            "type": "command",
            "command": "node \"${extensionPath}${/}dist${/}hooks${/}single_edit_per_turn_hook.cjs\"",
            "description": "同一ターン内での同一ファイルへの複数回編集を阻止します。"
          }
        ]
      }
    ],
    "AfterAgent": [
      {
        "matcher": "*",
        "hooks": [
          {
            "name": "single-edit-per-turn-reset",
            "type": "command",
            "command": "node \"${extensionPath}${/}dist${/}hooks${/}single_edit_per_turn_hook.cjs\"",
            "description": "ターン終了時にファイル編集制限をリセットします。"
          }
        ]
      }
    ]
  }
}
```

### 3. ビルド設定の更新 (`tools/build.cjs`)
- `const hooks = [...]` 配列に `'hooks/scripts/single_edit_per_turn_hook.cjs'` を追加する。

## ゴール
- 1つのターン内で同一ファイルに2回以上の `replace`/`write_file` を実行しようとした際、2回目以降が即座にブロックされ、エラーメッセージがモデルに返されること。
- 異なるファイルであれば、同一ターン内でも複数回の編集が許可されること。
- `AfterAgent` 実行後（次のターン開始時）には、再び同じファイルへの編集が可能になること。

## 検証手順

### 1. 単体テストの作成 (`tests/hooks/single_edit_per_turn_hook.test.js`)
`vitest` を使用し、以下のシナリオを網羅する。
- [ ] `BeforeTool`: 初回の `write_file` が `allow` されること。
- [ ] `BeforeTool`: 同一セッションでの2回目の `replace` が `deny` されること。
- [ ] `BeforeTool`: 別の `file_path` であれば 2回目でも `allow` されること。
- [ ] `AfterAgent`: 実行後に記録ファイルが削除されること。
- [ ] `AfterAgent` 実行後、再び `BeforeTool` で同じファイルへの編集が `allow` されること。

### 2. 統合検証
- `npm run build` を実行。
- 実機（Gemini CLI）で以下のプロンプトを実行し、期待通りの挙動を確認する。
  - 「同一ファイル A に対して 2 回 `replace` を行え」 -> 2回目がブロックされること。
  - 「ファイル A とファイル B に対して 1 回ずつ `replace` を行え」 -> 両方成功すること。
