# Issue: コーディングルール自動注入フックの実装

## 概要
`.agent/rules/*.md` に記述されたプロジェクト固有のコーディングルールを、`read_file` ツールでファイルを読み込む際に自動的にコンテキストへ注入するフックを実装する。

## 背景と問題点
大規模なプロジェクトや特定のライブラリを使用するプロジェクトでは、ファイルごとに適用すべきコーディングルールが存在する。
現在、ユーザーは手動でルールを提示するか、エージェントが自発的にルールファイルを探す必要があるが、これではルールの見落としや手間の増加を招く。
特に、特定の拡張子（例: `*.ts`）に対して一貫したルールを適用したい場合に、自動的な注入が求められている。

## 解決策
`AfterTool` フックイベントを利用し、`read_file` ツールの実行後に介入する。
`.agent/rules/` ディレクトリ内の Markdown ファイルからフロントマター（`trigger: glob`, `globs: ...`）を解析し、読み込まれたファイルのパスがグロブパターンに一致する場合、そのルールの内容を `additionalContext` としてモデルに提供する。

## 実装内容詳細
1. **フックスクリプトの作成**: `hooks/scripts/coding_rules_hook.cjs`
   - 入力 JSON から `read_file` の `file_path` を取得。
   - `.agent/rules/` 内の全 Markdown ファイルを走査。
   - フロントマターを解析し、一致するグロブパターンのルールを抽出。
   - `decision: "allow"` と共に `hookSpecificOutput.additionalContext` にルールを込めて出力。
2. **ビルド設定の更新**: `tools/build.cjs` に新スクリプトを追加。
3. **フック設定の更新**: `hooks/hooks.json` の `AfterTool` セクションに登録。
   - `matcher`: `read_file`
4. **テストの追加**: `tests/hooks/coding_rules_hook.test.js` を作成し、モックデータで動作を検証。

## ゴール
- `.agent/rules/test.md` に `globs: *.ts` が指定されている場合、`read_file("src/main.ts")` の後にそのルールがコンテキストとして注入されること。
- ルールが存在しない場合は、通常のツール実行結果のみが返されること。
- フロントマターの解析が正しく行われること。
