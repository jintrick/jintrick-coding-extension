# Issue: コーディングルール自動注入フックの実装

## 概要
`read_file` ツール実行後に `.agent/rules/*.md` を走査し、ファイルパスに合致するルールを `additionalContext` として注入する `AfterTool` フックを実装する。

## 実装内容詳細

### 1. フックスクリプト: `hooks/scripts/coding_rules_hook.cjs`
標準モジュールのみを使用し、外部依存（`minimatch`, `js-yaml` 等）を追加しない。

- **実行条件**: `hook_event_name === 'AfterTool'` かつ `tool_name === 'read_file'`。
- **入力解析**: `stdin` から JSON を取得し、`tool_input.file_path` を抽出。
- **ルール走査**: `${cwd}/.agent/rules/*.md` を同期的に走査する（直下のみで可）。
- **フロントマター解析**:
  - `---` で囲まれたブロックを正規表現 `/^---(?:\r?\n)([\s\S]*?)(?:\r?\n)---(?:\r?\n)?([\s\S]*)$/` で抽出。
  - フロントマター内を `key: value` 形式でパースし、`trigger: glob` および `globs`（文字列または `-` 形式のリスト）を取得。
- **グロブ照合 (`matchGlob`)**:
  - `file_path` の `\` を `/` に正規化。
  - グロブパターンを以下の置換により正規表現へ変換して照合：
    - `.` -> `\.`
    - `**` -> `.+`
    - `*` -> `[^/]+`
    - `?` -> `.`
- **レスポンス形式**:
  - `decision: "allow"`
  - `hookSpecificOutput.additionalContext`: 
    ```text
    
    [RULE APPLIED: ${filename}]
    ${content}
    ```
    （複数マッチ時は結合する）

### 2. 環境統合
- **ビルド**: `tools/build.cjs` の `hooks` 配列に `hooks/scripts/coding_rules_hook.cjs` を追加。
- **設定**: `hooks/hooks.json` の `AfterTool` セクションに以下を登録：
  - `matcher`: `^read_file$`
  - `name`: `coding-rules-hook`
  - `command`: `node "${extensionPath}${/}dist${/}hooks${/}coding_rules_hook.cjs"`

### 3. 検証
- **tests**: `tests/hooks/coding_rules_hook.test.js` を作成し、`vitest` で実行。
- **検証項目**: 
  - フロントマターの正常パース。
  - `globs` による単一/複数ファイルの合致.
  - `trigger` 条件（`glob` 以外を無視）の確認。
  - ルール未発見時の正常終了（`additionalContext` なし）。

## ゴール
- `.agent/rules/test.md` (`globs: *.ts`) が存在するとき、`read_file("src/main.ts")` 実行直後にルール内容が注入される。
- `npm run build` および `npm test` が正常に完了する。

## Appendix: 技術的選定理由 (Why/Why Not)

### なぜ `---` (YAML形式) で区切るのか (Why)
- **Antigravity 互換性**: 外部エージェント Antigravity が標準的に採用しているルール記述形式（`.agent/rules/*.md`）と共通化するため。これにより、単一のルールファイルで Gemini CLI と Antigravity 両方の振る舞いを制御可能にする。
- **視認性と普及度**: Markdown エコシステムにおいて最も普及しているメタデータ記述方式であり、エディタのハイライト表示等の支援を受けやすい。

### なぜ外部パッケージ (js-yaml, minimatch 等) を使用しないのか (Why Not)
- **フックの軽量化**: フックはツール実行のたびに起動されるため、依存関係を排除してバンドルサイズと起動オーバーヘッドを最小化する。
- **エッジケースの制御**: `minimatch` 等の汎用ライブラリは複雑なパターンをサポートするが、本件で必要なのは `*`, `**` 等の基本要素のみである。自前で正規表現変換を行うことで、Windows/Unix 間のパス正規化（`\` と `/` の差異）をより直接的かつ確実に行える。
- **依存性リスクの排除**: 外部ライブラリの脆弱性や破壊的変更の影響を受けず、標準モジュールのみで完結させることで長期的な保守性を高める。
