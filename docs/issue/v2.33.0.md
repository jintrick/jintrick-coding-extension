# Issue: issue-closer の自律的バリデーション強化（水際番人化）

## 背景と問題点 (Why)
issue-closer は単なるクローズ処理の自動化ツールに留まっており、マージ前の品質担保（ビルド忘れ、差分の混入、DoDの未チェック、不適切なLint抑制）が物理的に強制されていない。このため、不完全または整合性が取れていない状態のコードがリリースされるリスクが存在する。

## 解決策 (What)
`agents/issue-closer.md` を改修し、マージ前の Strict Verification (物理的ガードレール) および Qualitative Lint Review (知性的ガードレール) を導入する。エージェントの責務を「単なるクローズ処理」から「リリースを水際で守る番人」へと再定義する。

## 実装内容詳細 (How)
1. `agents/issue-closer.md` のフロントマターを編集した。
   - `description` を「プロジェクトの品質と整合性を水際で守り、安全が確認された場合のみリリースを許可する番人」の旨へと書き換えた。
2. エージェントのプロンプト内に「物理的ガードレール (Strict Verification)」の手順を追加した。
   - マージ操作前に `npm run build` を実行する指示を明記。
   - ビルド後に `git status` を確認し、未コミット差分が検出された場合は直ちに処理を拒否する指示を明記。
   - 対象 Issue 文書の DoD を読み取り、全ての項目が `- [x]` であるか物理的に検証し、未達があれば拒否する指示を明記。
3. エージェントのプロンプト内に「知性的ガードレール (Qualitative Lint Review)」の手順を追加した。
   - `git diff` 等から `eslint-disable` 系のコメントを抽出する指示を明記。
   - 抽出したコメントの `--` 以降の理由を評価し、怠慢や一時的な逃げで技術的妥当性がないと判断した場合は拒否する指示を明記。
