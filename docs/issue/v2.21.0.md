# Issue: issue-sync.cjs の全件同期廃止と日付上書きロジックの是正

## 背景と問題点
`issue-sync.cjs` が特定の Issue ブランチを特定できない場合に `docs/issue/` 下の全ファイルを同期対象とするロジックにより、意図しない大量のファイル更新（主にステータスの `in-progress` への書き換えや日付の上書き）が発生する。また、Git 履歴に基づく `created` の上書きが既存の明示的な日付入力を無視して行われるため、データの整合性が損なわれている。

## 解決策
- `require.main` 実行時のディレクトリ全件スキャン・同期ロジックを削除する。
- `syncIssue` 関数内での `created` フィールド更新において、既存の値が有効な日付（yyyy-mm-dd 形式）である場合は Git 履歴による上書きをスキップする。

## 実装内容詳細
### 1. `created` フィールド更新ロジックの変更
`skills/release-manager/scripts/issue-sync.cjs` の `syncIssue` 内で、以下の条件判断を実装する：
- 既存の `created` 行を取得。
- 値が `yyyy-mm-dd`（プレースホルダー）であるか、空、あるいは行自体が存在しない場合のみ、以下の優先順位で補完する。
    1. `getFirstCommitDate(filePath)` の戻り値
    2. 本日の日付（ISO 形式）

### 2. 全件同期ロジックの削除
`if (require.main === module)` ブロック内の `// Fallback: Sync all issues...` セクションを完全に削除する。
- `branchId` が特定できない、または対応する Issue ファイルが存在しない場合は、警告を表示して正常終了（または必要に応じてエラー終了）させる。

## 規約準拠 (Rule Compliance)
- `comment-preservation.md`: ロジック変更に合わせて、同期対象を単一の Issue に限定した意図をコメントに残すこと。

## ゴール
- Issue ブランチ以外で `issue-sync.cjs` が実行されても、既存の Issue ファイルが破壊（不本意な更新）されないこと。
- 手動で設定した `created` 日付がツールによって勝手に変更されないこと。

## Appendix: 技術的選定理由 (Why/Why Not)
- **安全倒しの設計**: 全件同期は `release-manager` の文脈では便利だが、不意の Git 操作ミスを誘発しやすいため、明示的な対象指定がない場合は「何もしない」のが最も安全であると判断した。
