# Issue: 新規サブエージェント `issue-closer` の定義と後始末の自動化

## 背景と問題点
Issue の「起草」を司る `issue-crafter` に対し、実装完了後の「後始末（Issue の最終化とリリース）」を一貫して担うサブエージェントが存在しない。その結果、ステータスの更新、マニフェストの同期、Git でのリリース操作といった一連の「完了作業」が手動のオーケストレーションに依存しており、非効率かつハルシネーションの温床となっている。

## 解決策
Issue のライフサイクルを完結させる専用サブエージェント `agents/issue-closer.md` を定義する。
このエージェントは `release-manager` スキルを拡張して、Issue を物理的に正装（完成）させ、続けてコミットからリリース（マージ・ブランチ削除）までを自律的に完遂する責務を負う。

## 実装内容詳細
### 1. `release-manager` スキルの拡張
- [x] `tools/issue-sync.cjs` を `skills/release-manager/scripts/issue-sync.cjs` へ移行。
- [x] `skills/release-manager/SKILL.md` を更新。`issue-sync.cjs` を用いた「Issue の同期と検証」を標準ワークフローに組み込み、リリースの前段階として定義する。
- [x] **`issue-sync.cjs` のゼロ引数化**: 引数を廃止。`git branch --show-current` から自動的に `docs/issue/<ID>.md` を特定し、検証・同期を行う仕様に修正する。

### 2. `agents/issue-closer.md` の作成
- [x] `agents/issue-closer.md` を作成。
- [x] **ワークフローの簡素化**: `TARGET_PATH` の特定をエージェントからスクリプト側へ移管。エージェントは引数なしで `node skills/release-manager/scripts/issue-sync.cjs` を呼び出す。

## ゴール
- 実装完了後に `issue-closer` を呼び出すだけで、ドキュメントの「正装」からリポジトリの「クリーンアップ（リリース）」までが自動で行われる。
