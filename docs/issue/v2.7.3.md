# Issue: system_prompt ストレージの設計正常化と gemini-cli-expert への統合

## 背景と問題点
現在、Gemini CLI のシステムプロンプト履歴は `knowledge/system_prompt/` に保存されている。しかし、`knowledge/` ディレクトリは本来「外部の技術スタック（React等）」を扱う場所であり、`tools/build.cjs` によって「プロジェクト内の特定ファイルの検出」を強制される設計となっている。
`system_prompt` は CLI 自身のメタ情報であり、プロジェクトの状態に依存する「外部知識」ではないため、現在の配置はビルドエラーの要因となり、設計的なねじれを生んでいる。

## 解決策
`system_prompt` のアーカイブ先を `knowledge/` から `skills/gemini-cli-expert/references/` へ移動し、CLI 自身の知識として `gemini-cli-expert` スキルに統合する。

## 実装内容詳細
1. **アーカイブ保存先パスの修正**: `hooks/scripts/system_prompt_monitor_hook.cjs` 内で定義されているシステムプロンプトのアーカイブ保存先パス（`targetDir`）を、`${extensionPath}/knowledge/system_prompt/` から `${extensionPath}/skills/gemini-cli-expert/references/system_prompts/` へ変更する。
2. **ビルドスクリプトの修正**: `tools/build.cjs` の `promoteKnowledge` から `system_prompt` の処理（および暫定的な `detector.json`）を削除する。
3. **スキルの更新**: `skills/gemini-cli-expert/SKILL.md` を修正し、`references/system_prompts/` 下の過去のプロンプト履歴も回答の参照対象に含めるよう指示を追加する。
4. **移行**: 既存の `knowledge/system_prompt/` 下のデータを新ディレクトリへ移動し、旧ディレクトリを削除する。

## ゴール
- `knowledge/` ディレクトリが純粋な「外部技術スタック用」に保たれ、ビルドプロセスが正常化する。
- Gemini CLI の仕様に関する知識が `gemini-cli-expert` スキルに集約され、エージェントがより正確に自身の仕様を回答できるようになる。
