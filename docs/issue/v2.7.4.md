# Issue: Git 操作専門サブエージェント git-expert の定義

## 背景と問題点
Gemini CLI のメインエージェントが Git 操作を直接行うと、以下の問題が発生する：
1. **Context Pollution**: `git diff` 等の巨大な出力が履歴を埋め尽くし、推論品質を低下させる。

## 解決策
Git リポジトリの状態管理、精密な変更制御、および安全な操作ワークフローに特化した汎用サブエージェント `git-expert` を `agents/git-expert.md` に定義する。このエージェントは特定のプロジェクト規約に依存せず、あらゆる Git リポジトリで動作する汎用的な設計とする。

## 実装内容詳細

### 1. リポジトリ・コンテキストのマッピング
*   **状態の要約**: `git status` や `git diff --stat` を駆使し、メインエージェントには「生ログ」ではなく「論理的な変更概要」のみを報告する。
*   **ハッシュ指定の徹底**: `git reset` や `git checkout` 等で履歴を移動する際、`HEAD~1` 等の相対指定を禁止し、必ずコミットハッシュを明示的に指定する。
*   **出力の最小化**: `git log` や `git reflog` を使用する際は、必ず `-n 10` 等のフラグを付与し、履歴取得によるコンテキスト汚染を最小限に抑える。

### 2. 精密な変更制御
*   **Atomic Staging**: `git add .` を原則禁止とし、変更意図に基づいたファイル単位の精密なステージングを行う。

### 3. ハイクオリティ・サマリー (Deterministic Summary)
メインエージェントへの完了報告は、以下の形式を標準とする：
- **Outcome**: Success / Failure (with reason)
- **Logical Change**: 変更された内容の意味論的な要約
- **Repository Health**: 現在のブランチ状態、未処理の変更の有無

## ゴール
- **Context Efficiency**: Git 操作に伴うメイン履歴のトークン消費を大幅に削減。
- **Operational Precision**: 相対指定の排除による誤操作の防止。

## Appendix: 技術的選定理由 (Why/Why Not)
- **Flashモデルの採用**: Git の状態把握やコマンド実行は、高度な推論よりも「速さ」と「正確な構文実行」が重要であるため、最新の gemini-3-flash-preview が最適である。
- **サブエージェント化**: 操作ログを別コンテキストに閉じ込め、メインエージェントの「短期記憶」をタスクの核心部分に集中させるため。
