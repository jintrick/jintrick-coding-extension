# Issue: Git 操作専門サブエージェント git-expert の定義

## 背景と問題点
Gemini CLI のシステムプロンプト（`.gemini/system.md`）では、「Git リポジトリに関連するすべてのタスク（検査、ステージング、コミット）を専門のサブエージェントに委譲せよ」と明記されている。
現在、本プロジェクトには Git 操作を専門とするサブエージェントが存在せず、メインエージェントがこれらの低レイヤー操作を直接行っている。
これにより、メインエージェントのコンテキストが浪費され、また Git 操作の安全性（意図しないファイルのステージング等）の保証がメインエージェントの判断に依存しているという課題がある。

## 解決策
Git リポジトリの検査（status, diff, log）、ステージング（add）、およびコミット（commit）を専門に担うサブエージェント `git-expert` を定義する。
`agents/git-expert.md` を新規作成し、`agents-spec.md` に示された「実戦から得られた設計原則」を適用する。

## 実装内容詳細
1. **エージェント定義ファイルの作成**: `agents/git-expert.md` を新規作成する。
2. **フロントマターの設定**:
   - `name`: `git-expert`
   - `description`: Git リポジトリの検査、ステージング、コミットを専門に扱う。
   - **`model`**: `gemini-3-flash-preview`（Git操作の軽快なレスポンスと、定型的な状態把握の効率化を優先するため）。
   - `tools`: `run_shell_command`, `read_file`, `grep_search`, `list_directory`, `glob`, `activate_skill` を許可する。
3. **システムプロンプトの記述（設計原則の適用）**:
   - **知識の動的ロード**: 
     - 起動直後に `activate_skill` を使用して `release-manager` スキルをロードし、プロジェクトのリリース規約を把握すること。
   - **事実ベースの強制と曖昧さの排除**:
     - 「適切に」「必要に応じて」「など」といった曖昧な表現を一切禁止する。
     - すべての操作（add, commit 等）の前に必ず `git status` を実行し、その出力を根拠に判断すること。
     - Windows (PowerShell) 環境での動作を前提とし、`&&` の使用を禁止する。
   - **安全規約**:
     - 破壊的な操作（reset, clean 等）は原則禁止とし、実行が必要な場合は必ず理由を説明すること。
     - `.env` や秘密情報が含まれる可能性のあるファイルが `git status` に現れた場合、即座に警告を発すること。
   - **完了報告の構造化 (Final Report)**:
     - 作業終了時、以下の形式でメインエージェントに報告すること。
       - **実施した Git 操作**: 具体的なコマンド一覧。
       - **現在のリポジトリ状態**: `git status` の要約。
       - **特記事項**: 発生した競合や、ステージングから除外したファイル等。

## ゴール
- `git-expert` サブエージェントが定義され、メインエージェントが Git 操作を安全かつ構造的に委譲できるようになる。
- システムプロンプト（`.gemini/system.md`）の指示に忠実なエージェント構成が実現される。
- メインエージェントが Git 操作の結果を「事実ベース」で受け取れるようになる。
