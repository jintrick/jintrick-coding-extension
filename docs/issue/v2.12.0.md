# Issue: single_edit_per_turn_hook の順次実行（wait_for_previous）の許容

## 背景と問題点
現在、同一ターン内での同一ファイルに対する複数回の `replace` 操作を阻止する `single_edit_per_turn_hook.cjs` は、呼び出しの形式に関わらず一律で2回目以降をブロックしています。
しかし、調査の結果以下のことが判明しました。
1. **並列実行の問題**: `wait_for_previous: true` なしで複数の `replace` を実行すると、変更が上書きされ消失する（物理的な不整合が発生する）。
2. **順次実行の安全性**: `wait_for_previous: true` を指定した順次実行であれば、先行する編集が完了した後の状態に対して次の編集が適用されるため、整合性が保たれる。

現在のフックは「安全な順次実行」まで妨げており、モデルが複雑な編集を1ターンで完遂することを不必要に制限しています。

## 解決策
フックのロジックを修正し、`wait_for_previous: true` が指定されている場合に限り、同一ファイルへの2回目以降の `replace` を許可します。

1. `BeforeTool` 実行時に `tool_input.wait_for_previous` を確認する。
2. 同一ファイルの編集記録がある場合でも、`wait_for_previous: true` であれば `allow` とする。
3. `wait_for_previous` が未指定または `false` の場合は、従来どおり `deny` とする。

## 実装内容詳細
- `hooks/scripts/single_edit_per_turn_hook.cjs` の修正
  - `tool_input.wait_for_previous === true` の判定追加
  - エラーメッセージを「並列実行の禁止」に特化した内容に更新

## ゴール
- 同一ターン内で同一ファイルに対する並列した `replace` は引き続きブロックされる。
- `wait_for_previous: true` を用いた順次実行であれば、同一ターン内での複数回 `replace` が成功する。
