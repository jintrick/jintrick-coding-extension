# Issue: issue-crafter による基盤整備タスクの自動分類精度の向上とバージョンインフレの抑制

## 背景と問題点 (Why)
起草専門サブエージェント `issue-crafter` が、将来の機能追加に向けた共通基盤の整備（型定義、Service の枠組み構築などの「土壌作り」）を `feat` や `refactor` として分類してしまう傾向がある。
本プロジェクトのツールチェーン (`infer-next-version.cjs`) ではこれらは「マイナーバージョン上昇 (Minor-up)」として処理されるため、ユーザーへの直接的な機能提供を伴わない内部作業によってマイナーバージョンが不当に上昇し続ける「バージョンインフレ」が発生している。

## 解決策 (What)
`issue-crafter` の判断基準を更新し、基盤整備タスクを「パッチバージョン上昇 (Patch-up)」対象である `chore` に割り当てるよう定義を明確化する。

1. **`agents/issue-crafter.md` の改訂**: 基盤整備（土壌作り）においては `refactor` ではなく `chore` を選択するよう、プロンプトに物理的な制約を追加する。
2. **`docs/reference/idd-flow.md` の更新**: `chore` がパッチバージョンの対象であり、かつ基盤整備を含むことをプロジェクト全体（および全エージェント）の共通認識として定義する。

## 実装内容詳細 (How)
1. **`agents/issue-crafter.md` の更新**:
    - タイプ選択の基準セクションに以下の指針を追加：
      - 「将来の機能追加に向けた基盤整備（型、Service 定義等の土壌作り）は、`refactor` ではなく `chore` を選択せよ。これにより不要なマイナーバージョン上昇を防ぎ、Patch-up として処理させる。」
2. **`docs/reference/idd-flow.md` の更新**:
    - タイプ定義の説明を追記：
      - `feat`, `refactor`: マイナーバージョン上昇 (Minor-up)。機能追加や構造的大規模改修。
      - `chore`, `fix`, `docs`: パッチバージョン上昇 (Patch-up)。基盤整備（土壌作り）、不具合修正、文書更新。

## 規約準拠 (Rule Compliance)
- **comment-preservation.md**: ドキュメントの既存の役割を維持しつつ、分類基準の解釈のみを更新する。
