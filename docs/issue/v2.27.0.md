# Issue: 基盤整備タスクの不適切なマイナーバージョン上昇の防止と chore 定義の明確化

## 背景と問題点 (Why)
将来の機能追加に向けた共通基盤の整備（型定義、共通 Service の枠組み、通信基盤の構築など、いわゆる「土壌作り」）が、現在は `feat` や `refactor` として分類される傾向がある。現行のツールチェーン (`infer-next-version.cjs`) ではこれらは「マイナーバージョン上昇 (Minor-up)」として処理されるが、ユーザーへの直接的な機能提供を伴わない基盤整備においてマイナーバージョンが上昇し続けるのは、セマンティックバージョニングの観点から不適切（バージョンのインフレ）である。

## 解決策 (What)
基盤整備タスクを「パッチバージョン上昇 (Patch-up)」として扱うため、既存の `chore` タイプにこれらのタスクを明示的に割り当てるよう定義を拡張・明確化する。
1. `agents/issue-crafter.md` のプロンプトを更新し、基盤整備タスク（将来のための土壌作り）は `refactor` ではなく `chore` を選択するよう指示を強化する。
2. `docs/reference/idd-flow.md` にタイプ別の定義（特に `chore` が Patch-up 対象であり、基盤整備を含むこと）を明記し、AIエージェントと人間の判断基準を統一する。

## 実装内容詳細 (How)
1. `agents/issue-crafter.md` の更新:
    - タイプ選択の基準セクションに以下の指針を追加する：
      - 「将来の機能追加に向けた基盤整備（型、Service 定義等の土壌作り）は、`refactor` ではなく `chore` を選択せよ。これにより不要なマイナーバージョン上昇を防ぎ、Patch-up として処理させる。」
2. `docs/reference/idd-flow.md` の更新:
    - タイプ定義の説明を追記：
      - `feat`, `refactor`: マイナーバージョン上昇 (Minor-up)。機能追加や構造的大規模改修。
      - `chore`, `fix`, `docs`: パッチバージョン上昇 (Patch-up)。基盤整備（土壌作り）、不具合修正、文書更新。
