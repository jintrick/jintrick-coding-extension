# Issue: Chrome DevTools MCP の統合によるブラウザ操作能力の提供

## 背景と問題点 (Why)
現状、ブラウザベースのデバッグや操作が必要な際、ユーザーが手動で外部 MCP サーバーを導入・設定する必要がある。これにより、本拡張機能が提供する「開発の自己修正ループ（Linter等）」をブラウザ上の UI 検証やパフォーマンス分析まで一貫して拡張できておらず、エージェントの自律的な問題解決能力が制限されている。

## 解決策 (What)
`chrome-devtools-mcp` を `gemini-extension.json` に MCP サーバーとして統合し、関連するデバッグ用 Skills を `skills/` ディレクトリに内包する。また、`GEMINI.md` を更新することで、エージェントがブラウザ操作能力を自身のツールセットとして認識・活用可能にする。

## 実装内容詳細 (How)
1. **gemini-extension.json の更新**:
   - `mcpServers` セクションに `chrome-devtools` を追加。
   - 実行コマンドは `npx -y chrome-devtools-mcp@latest` を使用し、常に最新のツールが利用可能にする。
2. **Skills の移行と配置**:
   - `skills/` ディレクトリに以下の 6 つのスキルディレクトリを作成し、[Chrome DevTools MCP リポジトリ](https://github.com/ChromeDevTools/chrome-devtools-mcp)から各 `SKILL.md` をコピー・配置する。
     - `a11y-debugging` (アクセシビリティ調査)
     - `chrome-devtools` (基本操作)
     - `chrome-devtools-cli` (CLI操作)
     - `debug-optimize-lcp` (LCP最適化)
     - `memory-leak-debugging` (メモリリーク調査)
     - `troubleshooting` (汎用トラブルシューティング)
   - 各スキルの `SKILL.md` 内のパス指定などが、本プロジェクトの構成と矛盾しないよう調整する。
3. **GEMINI.md の更新**:
   - 拡張機能がブラウザ操作能力（Chrome のデバッグポート経由）を持つことを明記する。
   - 必要に応じて、特定のタスク（UIの不整合修正、アクセシビリティ改善）においてこれらのスキルの使用を促す指示を追加する。

## 規約準拠 (Rule Compliance)
- `comment-preservation.md`: `gemini-extension.json` や `GEMINI.md` を編集する際、既存の JSDoc や意図を説明するコメントを破壊せず、変更内容に即した追記を行う。
- `no-temp-files-in-root.md`: 各スキルの設定やデバッグログ出力において、プロジェクトルートに一時ファイル（スクリーンショット等）が作成されないよう、OS 標準の一時ディレクトリを使用するよう指示を徹底する。

## ゴール
エージェントが `chrome-devtools` ツールを使用してブラウザ上の DOM 操作、ネットワーク監視、パフォーマンス計測、およびアクセシビリティ検証を自律的に実行し、報告・修正提案を行える状態になること。

## Appendix: 技術的選定理由 (Why/Why Not)
- **npx @latest の採用**: Chrome DevTools は更新が頻繁であり、かつ最新のブラウザ仕様に追従する必要があるため、依存関係として固定するよりも実行時に最新を取得する `npx` 方式を選択した。将来的にオフライン動作や起動速度が課題となる場合は、パッケージ内へのバンドルを検討する。
