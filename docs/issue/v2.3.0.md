# Issue: PowerShell 用 Linter Hook の実装と統合

## 概要
`linter_hook` に `.ps1` ファイルの構文検証機能を追加する。`pwsh` または `powershell` の AST (Abstract Syntax Tree) パース機能を利用し、書き込み前に構文エラーを検出・ブロックする仕組みを構築する。

## 背景と問題点
現状、`.ps1` ファイルへの `write_file` / `replace` 実行時に構文チェックが行われていない。これにより、閉じ括弧の欠如などの単純なミスがそのまま書き込まれ、実行時エラー（`toast_notification_hook` 等）を誘発するリスクがある。

## 解決策 (Technical Strategy)
1.  **Atomic Validator**: `hooks/scripts/linters/ps1.cjs` を新規作成し、PowerShell エンジンを介した構文チェックロジックをカプセル化する。
2.  **AST-based Verification**: `[System.Management.Automation.Language.Parser]::ParseInput` メソッドを使用して、スクリプトを実行せずに構文木を解析する。
3.  **Integration**: `linter_hook.cjs` および `tools/build.cjs` を更新し、新バリデーターをパイプラインに組み込む。

## 実装内容詳細

### 1. `hooks/scripts/linters/ps1.cjs` の実装
- **Execution**: `child_process.spawnSync` を使用。
- **Command Selection**: `pwsh` を優先し、失敗した場合は `powershell` を試行する（フォールバック）。
- **Validation Script**:
  ```powershell
  $content = [System.IO.File]::ReadAllText($args[0]);
  $errors = $null;
  [System.Management.Automation.Language.Parser]::ParseInput($content, [ref]$null, [ref]$errors);
  if ($errors) {
      $errors | ForEach-Object { "Line $($_.Extent.StartLineNumber): $($_.Message)" } | Out-String | Write-Error;
      exit 1;
  }
  ```
- **Output Interface**:
  - `valid: true`: 終了コード 0 の場合。
  - `valid: false`: 終了コード 1 の場合。`reason` に stderr の内容を含める。

### 2. `hooks/scripts/linter_hook.cjs` の修正
- `supportedExtensions` 配列に `'.ps1'` を追加し、ディスパッチ対象に含める。

### 3. `tools/build.cjs` の修正
- `hooks` 定数配列に `hooks/scripts/linters/ps1.cjs` を追加し、ビルド成果物として出力する。

## 受け入れ基準 (Acceptance Criteria)
- [ ] **Syntax Detection**: 不正な PowerShell 構文（例: `if ($true) {` の閉じ忘れ）を検出し、`decision: deny` を返すこと。
- [ ] **Detailed Error**: エラー発生時、行番号とエラー内容（PowerShell エンジンが返したもの）が `systemMessage` に含まれていること。
- [ ] **Safe Path**: 正常な PowerShell スクリプト（例: `Write-Host "Hello"`）が `decision: allow` で通過すること。
- [ ] **Environment Resilience**: `pwsh` が不在の環境でも、標準の `powershell` で動作すること（Windows限定）。

## 検証タスク (Test Cases)
1.  **正常系**: `write_file` で `Write-Output "Test"` を書き込み、成功することを確認。
2.  **異常系（構文エラー）**: `write_file` で `function Test {`（閉じ括弧なし）を書き込み、拒否されることを確認。
3.  **異常系（置換エラー）**: `replace` 実行後の結果が不正な構文になる場合に拒否されることを確認。
