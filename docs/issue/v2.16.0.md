# Issue: Enhance issue-closer to support Jules-integrated workflow

## 背景と問題点
現状の `issue-closer` サブエージェントおよび `idd-flow.md` は、作業ブランチが `vX.Y.Z` 形式であることを前提としており、外部エージェント (Jules) が生成した PR やブランチを介したフローに完全には対応していない。
Jules 連携時には、PR のマージ前にバージョン同期を行い、`gh pr merge --squash` を実行し、その後ローカルおよびリモートの作業ブランチをクリーンアップする必要がある。この手順が自動化・明文化されていないため、手動操作によるミスが発生するリスクがある。

## 解決策
`issue-closer.md` および `idd-flow.md` を更新し、ブランチ名の形式に基づいて「直接実装ケース」と「Jules 実装ケース」を自動判別し、それぞれに最適なクローズ処理を実行するように拡張する。

## 実装内容詳細

### 1. `agents/issue-closer.md` のプロンプト更新
以下のロジックをサブエージェントの動作指示に追加する。

#### ブランチ判別
- 現在のブランチ名を取得する。
- 形式が `vX.Y.Z`（例: `v2.16.0`）の場合：**直接実装ケース**として、既存の `release-manager` によるマージフローを実行。
- それ以外（例: `jules/feat-xyz`）の場合：**Jules 実装ケース**として判定。

#### Jules 実装ケースの処理フロー
1.  **事前確認**: `gh pr view` 等を実行し、現在のブランチが PR に紐付いているか確認する。
2.  **バージョン同期**: 
    - `release-manager` スキルを使用し、`package.json` 等のバージョンを今回の ID (vX.Y.Z) に同期させる。
    - 同期による変更（コミット）を `git push` で作業ブランチへ反映する。
3.  **PR マージ**:
    - `gh pr merge --squash` を実行する。
    - マージ成功後、GitHub 上のリモートブランチが削除されることを確認（`gh` コマンドのフラグ等で制御可能なら行う）。
4.  **ローカルクリーンアップ**:
    - `dev` ブランチへチェックアウトする。
    - ローカルの作業ブランチを `git branch -D` で削除する。
    - `git pull origin dev` を実行し、最新の状態を反映する。

### 2. `docs/reference/idd-flow.md` の更新
「ステージ 5: 検証と最終化」セクションに、Jules 連携時のクローズ手順を追記し、開発者が `/review` 合格後に `issue-closer` を起動すべきであることを明記する。
