# Issue: init-jintrick-project スキルの廃止と自動同期フックへの移行

## 背景と問題点
現状の `init-jintrick-project` スキルは手動実行が必要であり、また `package.json` を完全に上書きするなど破壊的で使い勝手が悪い。対象プロジェクトのルートに `package.json` または `.git` が存在するプロジェクトに対しては、`system.md` やエージェントルールの最新化を拡張機能のアップデートに合わせて自動化し、ユーザーの手間を減らす必要がある。

## 解決策
- `init-jintrick-project` スキルを完全に削除する。
- 既存キュ標準アセット（`.gemini/system.md`, `.agent/rules/*.md`）を `skills/jintrick-tools/assets/project-template/` へ移動する。
- `SessionStart` イベントにフックし、プロジェクトの有効性（`package.json` または `.git` の存在）を条件に自動同期を行う `project_template_sync_hook.cjs` を実装する。

## 規約準拠 (Rule Compliance)
- **comment-preservation.md**: 
  - `tools/build.cjs` や `hooks/hooks.json` への追記を行う際、既存のドキュメントやコメントの意図を破壊せず、変更に合わせた追記のみを行うこと。
- **no-temp-files-in-root.md**: 
  - フックでのファイルコピー処理において、プロジェクトルートに一時ファイルが作成されないよう、`fs.copyFileSync` などを利用して直接配置するか、メモリ上で処理すること。

## 実装手順
1. **アセットの再配置**:
   - `skills/init-jintrick-project/` 配下等にある `.gemini/system.md` および `.agent/rules/*.md` を、ディレクトリ構造を維持したまま `skills/jintrick-tools/assets/project-template/` へ移動・配置する。
   - 既存の `package.json` テンプレートアセットは廃止し、新しいテンプレートディレクトリには含めない。
2. **スキルの削除**:
   - `skills/init-jintrick-project` ディレクトリを削除する。
3. **フックの作成**:
   - `hooks/scripts/project_template_sync_hook.cjs` を作成する。
4. **フックのロジック実装**:
   - 実行条件: `${cwd}/package.json` または `${cwd}/.git` が存在する場合のみ同期処理を開始する。
   - 条件不一致時の処理: 条件を満たさずフックの処理をスキップする場合は、`systemMessage` プロパティを含めた JSON を返し、ユーザーに「有効なプロジェクト（package.json または .git 存在下）ではないため、jintrick 標準構成の同期をスキップしました」と通知すること。
   - 同期ロジック: `__dirname` またはパス解決を用いて拡張機能の `skills/jintrick-tools/assets/project-template/` を起点とし、ディレクトリ構造を再帰的に走査してターゲットへファイルをコピーする。
   - 上書き条件: ターゲットにファイルが存在しない場合は新規コピー。存在する場合は、ソースファイルの `mtime` がターゲットファイルの `mtime` より新しい場合のみ上書きする。
   - 通知: コピーまたは更新が 1 件でも発生した場合のみ、`systemMessage` プロパティを戻り値に含め、ユーザーに通知する。
5. **フックの登録**:
   - `hooks/hooks.json` の `SessionStart` 配列に `{ "id": "project-template-sync", "path": "${extensionPath}/dist/hooks/project_template_sync_hook.cjs" }` を追加する。
   - `tools/build.cjs` の `hooks` 配列（またはビルド対象の定義）に `project_template_sync_hook.cjs` を追加する。
