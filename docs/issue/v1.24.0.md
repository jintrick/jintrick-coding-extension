# Issue: tech-stack discovery におけるモノレポ（サブディレクトリ）対応

## 概要
`tech_stack_discovery_hook.cjs` のスキャン範囲を拡張し、モノレポ構成（`packages/*`, `apps/*` 等）のサブディレクトリ内に存在する技術スタックを正しく検出可能にする。

## 背景と問題点
現状の `tech_stack_discovery_hook.cjs` はプロジェクトルート (`cwd`) 直下のファイルのみを判定対象としている。
しかし、モダンな開発ではモノレポ構成が一般的であり、`package.json` や `pyproject.toml` がサブディレクトリに配置される。現在の実装ではこれらを検出できず、`tech-expert` サブエージェントの有効活用が妨げられている。

## 解決策
- `cwd` から指定した深度（最大2〜3階層）までのディレクトリを再帰的に走査する。
- パフォーマンス維持のため、`node_modules`, `.git`, `dist` 等の巨大または不要なディレクトリを除外する。
- 複数のスタックが検出された場合（例: フロントエンドは React、バックエンドは Python）、そのすべてをスタックとして認識する。

## 実装内容詳細
- [ ] `tech_stack_discovery_hook.cjs` にディレクトリ走査ロジックを追加。
- [ ] 探索深度制限（`maxDepth`）の実装。
- [ ] 無視リスト（`ignorePatterns`）の実装。
- [ ] 各 `tech-expert-*` スキルの `manifest.json` の `detectors` との互換性維持（または拡張）。

## ゴール
- モノレポ構造のテストプロジェクトにおいて、サブディレクトリ内の技術スタックが正しく検出され、システムメッセージが表示されること。
- 巨大なプロジェクトでも、フックの実行による遅延が許容範囲内（数百ミリ秒程度）であること。
