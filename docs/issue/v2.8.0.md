# Issue: 原因調査専用サブエージェント `bug-investigator` の追加

## 背景と問題点
LLMが不具合やテスト失敗の原因調査において、ログや実行結果の物理的証拠を確認する前に推測を原因と断定し、性急に修正案を提案して実装する問題が存在する。これにより、根本原因の特定を欠いた不正確な修正作業が繰り返されるリスクがある。

## 解決策
推測と事実を厳密に区別し、証拠に基づく原因究明のみを責務とする専用サブエージェント `agents/bug-investigator.md` を作成する。当該エージェントには修正案の作成やコード変更を禁止する。

## 実装内容詳細
1. `agents/bug-investigator.md` を新規作成する。
2. ファイル先頭に以下のYAMLフロントマターを定義する。
   - `name`: `bug-investigator`
   - `description`: 不具合やテスト失敗の根本原因を、物理的証拠に基づき特定する原因調査専門エージェント。修正の実装は行わない。
   - `tools`: `read_file`, `grep_search`, `run_shell_command`, `glob`
   - `max_turns`: 15
3. プロンプト本文に以下の拘束条件を明記する。
   - 責務: 修正作業やコード生成を禁止し、根本原因の特定を完了条件とする。
   - 推論と事実の分離: 推測（Hypothesis）と事実（Fact/Evidence）を区別して報告させる構造化フォーマットを定義する。
   - 証拠の要求: ログ、再現スクリプトの実行結果、変数のダンプのいずれかの物理的証拠が存在しない限り、原因と断定することを禁止する。
   - メカニズムの証明: 修正案の提示を禁止し、エラー発生のメカニズムをコードの実行フローに沿って証明することを要求する。

## ゴール
エージェントが推測に基づく修正コード生成を停止し、物理的証拠と実行フローに基づくエラーのメカニズム証明を完了した状態。

## テスト
- テスト対象 (What)
  - `agents/bug-investigator.md`
- テスト内容・目的 (Why)
  - サブエージェントが修正コードを生成せず、証拠の提示と実行メカニズムの証明を要求する挙動を検証する。
- 検証方法・手順 (How)
  1. `npm run build` を実行し、ビルド成果物を更新する。
  2. `npm test` を実行し、既存テストがすべてパスすることを確認する。
  3. Gemini CLIを起動し、`@bug-investigator` を呼び出してダミーのエラーログと対象コードを提示する。
  4. エージェントの回答が修正コードの提示ではなく、事実と推論の分離、および追加の物理的証拠の確認要求に限定されることを確認する。
