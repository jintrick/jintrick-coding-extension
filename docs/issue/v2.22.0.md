# Issue: 同一ファイルへの並列編集に対する自己治癒（wait_for_previous 注入）の実装

## 背景と問題点
現在、同一ターン内で同一ファイルに対して複数の編集（`replace`, `write_file`）が並列に計画されると、`single_edit_per_turn_hook.cjs` が `deny` を返し、実行を中断させる。
これは物理的な整合性（Race Condition）を防ぐための挙動だが、エージェントが `wait_for_previous: true` を単に付け忘れた場合でも手動でのプラン修正とリトライを強いるため、開発のテンポを阻害している。
安全性を維持しつつ、システム側で自動的に直列化（自己治癒）を行うことで、この摩擦を解消する必要がある。

## 解決策
`hooks/scripts/single_edit_per_turn_hook.cjs` を修正し、同一ファイルへのロック競合を検知した際に、`deny` するのではなく、`wait_for_previous: true` を `tool_input` に注入した上で `allow` を返すように変更する。

## 実装内容詳細
1.  **競合検知の維持**: `BeforeTool` において、`cacheFile` に対象 `filePath` が既に存在し、かつ `tool_input.wait_for_previous` が `true` でない状態を「自己治癒の対象」と判定する。
2.  **レスポンスの書き換え**: 上記の状態を検知した場合、従来の `deny` 処理の代わりに、以下の構造を持つ JSON を標準出力に返す。
    - `decision`: `"allow"`
    - `hookSpecificOutput.tool_input`: `{ "wait_for_previous": true }`（既存の入力にマージされる）
    - `hookSpecificOutput.systemMessage`: 自動修正を行った旨と、その理由（Race Condition 回避）を伝える通知メッセージ。
3.  **メッセージ内容**: 
    - 「【自己治癒】同一ファイルに対する並列編集を検知したため、整合性維持のために自動的に `wait_for_previous: true` を注入して実行を継続します。」といった内容にする。
4.  **例外処理**: 万一、`cacheFile` の読み書きに失敗した場合は、安全側に倒して（Fails Open） `allow` する既存の挙動を維持する。
