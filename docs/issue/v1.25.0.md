# Issue: tech-expert ナレッジ追加の Plug-and-Play 化 (Directory-based Skill Auto-Discovery)

## 概要
新しい技術スタックのナレッジを追加する際、ディレクトリ作成や `manifest.json` の記述（ボイラープレート）を不要にし、`knowledge/` ディレクトリにリファレンス群を含むフォルダを配置するだけで済むようにアーキテクチャを洗練させる。

## 背景と問題点
現状、ナレッジを追加するには `skills/tech-expert-<name>/` ディレクトリを作り、その中に `manifest.json` と `SKILL.md` を分担して書く必要がある。
しかし、`gemini-cli-expert` 級の膨大なナレッジ（`references/`）を扱う場合、単一 Markdown ファイルでは記述しきれず、かといって現在のボイラープレートな構成は拡張性が低い。

## 解決策：ディレクトリ・ベースの Plug-and-Play (Skill Promotion)
- **開発 (Authoring)**: ユーザーは `knowledge/<stack>/` というディレクトリを作成し、その中に自由にドキュメントを配置する。
- **ビルド (Build Step)**: `tools/build.cjs` を拡張し、ビルド時に以下の変換・補完を自動で行う。
  - `knowledge/*` 以下のサブディレクトリをスキャン。
  - `manifest.json` が欠落している場合、ディレクトリ内の主要ファイルから `detectors` を自動推論（例：`package.json` があれば node スタックとして推論）。
  - `SKILL.md` が欠落している場合、ディレクトリ名をスタック名として、汎用的な「RAG 専門家」の指示書を自動生成。
- **実行 (Runtime)**: `tech-expert` エージェントは、既存の `activate_skill` を使って、この「自動昇格されたスキル」をロードする。

## 実装内容詳細
- [ ] `knowledge/` ディレクトリの新設。
- [ ] `tools/build.cjs` の拡張:
  - `knowledge/` 以下のディレクトリ構造を、自動補完付きで `dist/skills/` へ展開するロジックの実装。
  - `manifest.json` および `SKILL.md` の自動生成テンプレート機能の追加。
- [ ] 既存の `skills/tech-expert-react/` および `skills/tech-expert-python/` を `knowledge/` へ移行。
- [ ] `docs/reference/tech-expert-spec.md` の更新。

## ゴール
- `knowledge/react/` というディレクトリを置くだけで、`manifest.json` や `SKILL.md` を書かなくとも、ビルド後にエージェントが React 専門家として機能すること。
- 大規模なナレッジベースも、そのままのフォルダ構造で「Plug-and-Play」として扱えること。
