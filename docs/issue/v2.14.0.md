# Issue: 新規スキル `init-jintrick-project` の作成

## 背景と問題点
jintrickの開発プロジェクトを新規に開始する際、標準的な設定ファイル（`.gemini/system.md`, `.agent/rules/`, `package.json` 等）を手動で配置するのは手間であり、一貫性が失われる可能性がある。これを自動化するスキルが必要である。

## 解決策
新規スキル `init-jintrick-project` を追加する。
このスキルは、jintrick プロジェクトの標準テンプレート（アセット）を保持し、実行時にプロジェクトルートへ配備する。既存ファイル（特に `package.json`）とのコンフリクト時には、安全に処理を中断し、ユーザーに上書きの判断を仰ぐか、手動マージを促す仕組みを提供する。

## 実装内容詳細
### 1. スキル構造の定義
`skills/init-jintrick-project/` ディレクトリに以下の構成で作成する：
- `SKILL.md`: スキルの定義、プロンプト指示、使用方法。
- `assets/`: プロジェクト初期化用のアセット群。
  - `.gemini/system.md`: 基本的なシステムプロンプト。
  - `.agent/rules/`: `comment-preservation.md`, `no-temp-files-in-root.md` 等の標準規約。
  - `package.json`: jintrick 推奨設定を含むテンプレート。
  - `README.md`: 初期プロジェクト用のスターターガイド。
- `scripts/init_project.cjs`: アセットの配備ロジック。
- `references/`: 補助資料（もしあれば）。

### 2. 初期化スクリプト (`init_project.cjs`) の挙動
- **カレントディレクトリの取得**: 実行時のプロジェクトルートを特定する。
- **アセットのコピー**: `assets/` 内のファイルを再帰的にコピーする。
- **コンフリクト検出**: 
  - `package.json` が既に存在する場合、上書きせず警告を表示して終了する。
  - `--force` 引数が指定されている場合のみ上書きを許可する。
  - その他のファイル（`.agent/rules/` 内など）についても、既存ファイルがある場合は同様の処理を行う。
- **後処理**: `npm install` の実行を促すメッセージを表示する。

### 3. `gemini-extension.json` への登録
- 新規スキル `init-jintrick-project` をマニフェストに追加する。

## 規約準拠 (Rule Compliance)
- **comment-preservation.md**: `init_project.cjs` およびアセット内の各ファイルにおいて、意図を説明するコメントを維持・記述する。
- **no-temp-files-in-root.md**: 初期化プロセス中にプロジェクトルートに一時ファイルを作成しない。
