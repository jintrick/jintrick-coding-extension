# Issue: バージョン推論ロジック (inferNextVersion) の独立したスクリプトへの分離

## 背景と問題点
現在、次期バージョンの推論ロジック (`inferNextVersion`) は `generate-template.cjs` 内に直接記述されている。このため再利用性が欠如している。

## 解決策
1. **ロジックの抽出**: `infer-next-version.cjs` を新規作成し、`inferNextVersion` 関数の実体をここに移動する。引数なしで現在のプロジェクトのバージョンを自動取得する機能を備える。
2. **責務の変更**: `generate-template.cjs` の責務を「ファイル（`docs/issue/vX.Y.Z.md`）の物理的な作成」に拡張する。
3. **既存スクリプトのリファクタリング**: `generate-template.cjs` からインラインロジックを削除し、新規スクリプトを `require` して使用するように修正する。
4. **エージェント定義の更新**: `issue-crafter.md` のワークフローを、新設されたツール群を適切な順序で利用するように再定義する。また、責務を「案の提示」から「物理的な作成・完結（コミット）」へ拡大する。

## 実装内容詳細

### 1. `skills/jintrick-tools/scripts/infer-next-version.cjs` の新規作成
- `inferNextVersion(version, type)` および `getCurrentVersion()` を定義し、`module.exports` する。
- CLI モードでは、引数が不足している場合に `getCurrentVersion()` を利用して推論を行う。

### 2. `skills/jintrick-tools/scripts/generate-template.cjs` の修正
- 物理ファイル `docs/issue/${id}.md` を作成する処理を追加。
- `infer-next-version.cjs` を利用してバージョン情報を取得・計算する。

### 3. `agents/issue-crafter.md` の修正
- スキル起動を最初に行い、`infer-next-version.cjs` で ID を確定してからブランチを切るよう手順を修正。
- `generate-template.cjs` を実行してファイルを物理作成させ、その内容を Ground Truth として設計を行うよう指示。
- `write_file`, `replace` ツールを追加し、設計内容を Issue ファイルに直接書き込み、`git commit` して Stage 3 を完遂する指示を追加。
- **宣言的アプローチへの移行**: 従来の硬直したステップバイステップの「ワークフロー」を廃止し、「Ultimate Goal (最終目標)」「Available Assets (活用すべき資産)」「Guardrails & Constraints (絶対の拘束条件)」から成る宣言的なプロンプト構造に刷新。状況（既にブランチにいる等）に応じて自律的に最適な手順を組み立てられるようにした。

### 4. テストの整備
- `tests/infer-next-version.test.js` を新規作成。
- `tests/generate-template.test.js` をファイル作成仕様に合わせて更新。

## ゴール
- `node skills/jintrick-tools/scripts/infer-next-version.cjs feat` を実行すると現在のプロジェクトの次期マイナーバージョンが出力される。
- `node skills/jintrick-tools/scripts/generate-template.cjs` を実行すると `docs/issue/vX.Y.Z.md` が物理作成される。
- `issue-crafter` サブエージェントが、迷いなく物理的事実に基づいた Issue を作成・確定できる。
