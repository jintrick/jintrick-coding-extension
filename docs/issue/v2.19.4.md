# Issue: 並列編集防止Hookのエラーメッセージ刷新と対象ツールの拡充

## 背景と問題点
現在、`single_edit_per_turn_hook.cjs` は `replace` ツールのみを制限対象としており、エラーメッセージも「外科的編集（replace）の重複」という文脈で記述されている。
このため、エージェントがエラーに遭遇した際、ツールの不具合や `replace` 固有の制約と誤認し、`write_file` など別のツールに切り替えて並列実行を継続しようとする「迷走」が発生している。
本来、同一ファイルへの複数の書き込み操作は、ツールの種類に関わらず物理的に順次実行（直列化）されるべきであり、並列プランニングそのものが物理的に破綻していることを明確に伝える必要がある。

## 解決策
- `single_edit_per_turn_hook.cjs` のエラーメッセージを、「物理的並列実行エラー（PHYSICAL CONCURRENCY ERROR）」および「ファイルロック」を強調する形式に刷新する。
- 制限対象ツールを `replace` に限定せず、`write_file` などファイル内容を書き換える主要ツールに拡充する。
- どのツールが競合しているかをエラーメッセージに含め、エージェントが状況を正確に把握できるようにする。

## 実装内容詳細
1. `single_edit_per_turn_hook.cjs` の `tool_name` 判定を、`replace` と `write_file` を含むリスト形式（`['replace', 'write_file']`）に変更する。
2. ロックファイル（`modifiedFiles`）のデータ構造を `Record<FilePath, ToolName>` に変更し、以前どのツールがそのファイルを編集したかを保存するように拡張する。
3. `deny` 関数の呼び出し時のメッセージを以下のように修正する（エージェントが「回避不能」であることを悟るように設計）：
   - `reason`: `[PHYSICAL CONCURRENCY ERROR] File is LOCKED: ${filePath}`
   - `systemMessage`: 
     ```
     【物理的並列実行エラー】対象ファイルは現在ロックされています。
     同一ターン内に同一ファイルに対して複数の編集ツール（replace, write_file 等）を並列にプランニングすることは物理的に不可能です。
     ツールを変更（例: replace から write_file へ）しても、同一ファイルへの並列アクセスである限り、このエラーは回避できません。
     
     原因: あなたの現在の実行プランは、物理的な不整合（Race Condition）を引き起こす構成になっています。
     解決策:
     1. プランを修正し、同一ファイルへの操作には 'wait_for_previous: true' を付与して直列化してください。
     2. または、複数の変更を1つのツール呼び出しに集約してください。
     
     競合ツール: ${current_tool} (現在) vs ${previous_tool} (実行待ち)
     ```
4. `tests/hooks/single_edit_per_turn_hook.test.js` を更新し、新メッセージの検証と `write_file` の衝突テストを追加する。
