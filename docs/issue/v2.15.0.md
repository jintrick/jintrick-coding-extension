# Issue: Optimize command_fixer_hook.cjs for PowerShell 7 and implement dynamic POSIX-to-PS alias conversion.

## 背景と問題点
現在の `command_fixer_hook.cjs` は PowerShell 5.1 互換性のために `&&` を `;` に置換しているが、モダンな環境（PowerShell 7）では `&&` が標準サポートされている。
また、AI が生成する POSIX コマンド（`rm -rf`, `mkdir -p`, `which` 等）は、PowerShell のエイリアスやフラグの挙動と乖離があり、実行エラーや予期せぬ挙動を招く原因となっている。
特に前回のレビューにおいて、以下の致命的な欠陥が特定された：
1. **未知のフラグの破損**: `ls -t dir` 等の未知のフラグがカンマ区切りで結合され、構文エラーを招く。
2. **引数マッピングの不備**: `cp a b dest` 等の複数ソース指定が PowerShell 形式に変換されない。
3. **バックグラウンド演算子の誤飲**: `rm file & ls` が `Remove-Item file, ls &` になり、意図しない削除を招く危険がある。

## 解決策
- `command_fixer_hook.cjs` における `&&` から `;` への置換ロジックを削除し、PowerShell 7 のネイティブな動作を許容する。
- 以下の POSIX コマンドに対する動的な PowerShell 変換ロジックを実装する。
  - `rm` -> `Remove-Item`
  - `mkdir` -> `New-Item -ItemType Directory`
  - `cp` -> `Copy-Item`
  - `ls` -> `Get-ChildItem`
  - `which` -> `Get-Command`

## 実装内容詳細
- **&& 置換の削除**: `originalCommand.replace(/ && /g, ' ; ')` を削除。
- **堅牢なトークナイズ処理**:
  - クォート（`'`, `"`）内のセパレータを無視。
  - **バックグラウンド演算子の識別**: `2>&1` 等のリダイレクトに含まれる `&` と、セパレータとしての `&`（コマンド末尾）を厳密に区別してトークナイズする。
- **引数解析・再構成エンジンの刷新**:
  - **引数の分類**: `extraFlags`（フラグ）、`positionals`（パス/引数）、`redirections`（リダイレクト）を個別に収集。
  - **未知のフラグの保護**: スクリプトで定義されていない `-` で始まる引数は、そのまま `extraFlags` として保持（カンマ結合しない）。
  - **複数引数の適正な結合**: `rm`, `mkdir`, `ls` において、複数のパス指定がある場合にのみカンマ区切り（`, `）で結合し、パラメータの順序を維持する。
  - **cp コマンドの特別扱い**: `cp a b dest` 等の複数引数を、PowerShell の `Copy-Item -Path a, b -Destination dest` 形式（または適切な等価形式）に変換する。
- **フラグマッピングの適正化**:
  - `rm`: `-rf` -> `-Recurse -Force`, `-f` -> `-Force`, `-r` -> `-Recurse`
  - `mkdir`: `-p` は削除（`-ItemType Directory -Force` で再帰作成を代行）。
  - `cp`: `-r` -> `-Recurse`
  - `ls`: `-a` が含まれる場合は `Get-ChildItem -Force`、それ以外は `Get-ChildItem`。

## ゴール
- [ ] `&&` を含むコマンドがそのまま実行される。
- [ ] **安全なバックグラウンド実行**: `rm file & ls` が分割され、`Remove-Item file & Get-ChildItem`（または等価）に変換される。
- [ ] **未知のフラグの維持**: `ls -t dir` -> `Get-ChildItem -t dir` (カンマ区切りにならない)。
- [ ] **複数パスの正確な削除**: `rm a b` -> `Remove-Item a, b`。
- [ ] **リダイレクトの保護**: `npm install 2>&1` が破壊されず維持される。
- [ ] `mkdir -p <path>` が `New-Item <path> -ItemType Directory -Force` に置換される。
- [ ] `ls -a` が `Get-ChildItem -Force` に置換される。
- [ ] 意図しない箇所（クォート内、単語の一部）での置換が発生しない。

## テスト (追加ケース)

## Appendix: 技術的選定理由 (Why/Why Not)
- **なぜ `&` をセパレータとして扱うのか**: `rm a & ls` が一つのコマンドとして結合されると、PowerShell では `ls` を `rm` の引数と見なし、意図しない削除を招く。これを防ぐには、`&` を文脈（リダイレクト以外）でセパレータとして認識し、ステートメントを分割する必要がある。
