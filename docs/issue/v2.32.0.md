# Issue: agy と gc の協調動作を担う agy-client スキルおよび MCP サーバーの実装

## 背景と問題点 (Why)
gc と agy を連携させた開発ワークフローにおいて、「計画策定 → 人間の承認 → 実装」のプロセスを標準入出力の直接制御など不安定な方法で行うと、状態の非同期化やパースエラーが発生するリスクがある。標準的かつ安全なプロトコルによる状態同期が不可欠である。

## 解決策 (What)
ファイルシステム（`.agents/sync_state.json`）をバックエンドとした stdio ベースの MCP サーバーを導入し、それを gc 側から操作するための単一統合スキル `agy-client` を実装する。

## 実装内容詳細 (How)
1. **MCP サーバー (`skills/agy-client/mcp/index.js` 等)**
   - Node.js で stdio MCP サーバーを実装する。
   - ツール `request_approval(phase, artifact_path)` を提供する。
   - ツール実行時、`.agents/sync_state.json` に状態（例: `{"status":"pending", "phase": phase, "artifact": artifact_path}`）を書き込む。
   - `fs.watch` により同ファイルを監視し、`status` が `approved` または `rejected` に変更されるまで意図的にレスポンスをブロック（待機）する。

2. **クライアントスクリプト (`skills/agy-client/scripts/client.cjs`)**
   - 以下の CLI コマンド（または関数エクスポート）を実装する。
   - `status`: `.agents/sync_state.json` を読み取り、待機中（`pending`）の計画書パス等を出力する。
   - `approve`: 同期ファイルの `status` を `approved` に更新し、MCP サーバーのブロックを解除する。
   - `reject`: ユーザーのフィードバックを受け取り、同期ファイルの `status` を `rejected`（およびフィードバック内容）に更新する。

3. **スキル定義 (`skills/agy-client/SKILL.md`)**
   - gc 向けに「agy の状態を監視し、計画書を読み取り、ユーザーに報告・承認確認を行う」ワークフローを指示する。
   - `status`, `approve`, `reject` コマンドの用途と実行手順を定義する。

## Appendix: 技術的選定理由 (Why/Why Not)
- **ファイルシステムをバックエンドにする理由**: stdio でプロセス間通信を行う場合、標準出力の直接パースではノイズが混入しやすいため、ファイルシステムを用いた監視機構（`fs.watch`）が最も堅牢かつ実装の独立性を保てると判断した。
