# Issue: tech-expert エージェントの役割明確化とフック指示の適正化

## 概要
`tech-expert` サブエージェントが論理デバッグなどの「推論」が必要なタスクまで引き受けてしまい、不適切な回答を行う問題を修正。役割を「技術仕様の抽出（RAG）」に限定し、メインエージェントへの指示を弱める。

## 背景と問題点
- **過剰な委任**: `tech_stack_discovery_hook.cjs` が「エラー解決は必ず `tech-expert` に委ねよ」と強い命令を出していたため、メインエージェントが自律的なデバッグ（論理思考）を放棄していた。
- **ハルシネーションの誘発**: `tech-expert` がドキュメントにないプロジェクト固有のバグに対し、無理に推論で答えようとして「頓珍漢な回答」を生成していた。

## 解決策
- **役割の再定義**: `tech-expert` は「公式仕様・ベストプラクティスの抽出」に特化させ、推論によるコード生成やデバッグを禁止する。
- **フック指示の修正**: メインエージェントへの通知を「技術仕様の裏取りが必要な場合のみ利用せよ」という補完的な表現に変更し、デバッグの主権をメインエージェントに戻す。

## 実装内容詳細
1. **`agents/tech-expert.md` の修正**:
   - 役割を「ナレッジ抽出専門」と明記。
   - 禁止事項として「ドキュメントに基づかない推論」「独自の修正案提示」を追加。
2. **`hooks/scripts/tech_stack_discovery_hook.cjs` の修正**:
   - `additionalContext` 内の命令文を、技術スタックの仕様調査が必要な場合に限定する表現へ変更。
   - メインエージェントに論理的デバッグを継続するよう促す文言を追加。

## ゴール
- メインエージェントがライブラリの仕様確認が必要な時のみ `tech-expert` を呼び出すこと。
- `tech-expert` が「ドキュメントに情報がない」場合に正直に回答し、無理な推論を行わないこと。
