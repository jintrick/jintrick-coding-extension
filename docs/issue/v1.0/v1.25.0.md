# Issue: tech-expert ナレッジ追加の真の Plug-and-Play 化 (Zero-config Skill Promotion)

## 概要
`tech-expert` スキル追加時に必要だった `manifest.json` と `SKILL.md` の手動作成を廃止し、`knowledge/` ディレクトリにドキュメントを配置するだけで自動的に Skill として「昇格（Promotion）」させる仕組みを導入する。これにより、人間が JSON 形式の検知ルールを記述する手間を排除し、完全なプラグアンドプレイを実現する。

## 背景と問題点
現在、新しい技術スタックのナレッジを追加するには、`skills/tech-expert-*` ディレクトリを作成し、手動で `manifest.json` (検知ルール) と `SKILL.md` (指示書) を記述する必要がある。
この `manifest.json` は `tech-expert` エージェントの discovery hook のための内部プロトコルであり、開発者がこれを直接管理することはボイラープレートの増大を招き、プロジェクトの「Auto Discovery」原則に反している。
また、ドキュメントの配置場所と Skill 定義が密結合しているため、ナレッジの純粋な追加・削除が困難になっている。

## 解決策
1. **Source of Truth の分離**: ナレッジのソースとして `knowledge/` ディレクトリを新設し、各技術スタックをサブディレクトリ（例: `knowledge/react/`）として管理する。
2. **ビルド時自動昇格 (Zero-config Skill Promotion)**: `tools/build.cjs` に、`knowledge/` 内のディレクトリをスキャンし、`dist/skills/tech-expert-*` フォルダを自動生成するロジックを追加する。
3. **検知ルールの自動推論**: `knowledge/<stack>/` 内のファイル構成（`package.json`, `requirements.txt` 等）に基づき、`manifest.json` の `detectors` を自動生成する。
4. **指示書の自動生成**: `SKILL.md` が存在しない場合、ディレクトリ名を基に標準的な RAG 指示書を自動生成する。
5. **ランタイムの追従**: `tech_stack_discovery_hook.cjs` を更新し、ビルド済みの `dist/skills/` を優先的に参照するように変更する。

## 実装内容詳細

### 1. `knowledge/` ディレクトリの整備
- プロジェクトルートに `knowledge/` ディレクトリを作成する。
- 既存の `skills/tech-expert-react/` および `skills/tech-expert-python/` から、ドキュメント類（`references/` 内のコンテンツ）を `knowledge/react/` および `knowledge/python/` に移行する。
- 移行後、元の `skills/tech-expert-*` は削除する。

### 2. `tools/build.cjs` の拡張
- `promoteKnowledge()` 関数を実装し、以下の手順を実行する：
  - `knowledge/` 以下の各サブディレクトリ `<stack>` について：
    - `targetDir = path.join('dist/skills', 'tech-expert-' + <stack>)` を定義。
    - `manifest.json` の生成：
      - `knowledge/<stack>/package.json` が存在する場合：
        - `name = JSON.parse(package.json).name`
        - `detectors = [{ type: "file_contains", file: "package.json", pattern: '"' + name + '"' }]`
      - `knowledge/<stack>/requirements.txt` または `pyproject.toml` が存在する場合：
        - `detectors = [{ type: "file_exists", file: "requirements.txt" }, { type: "file_exists", file: "pyproject.toml" }]`
      - それ以外の場合：
        - `detectors = [{ type: "file_exists", file: <stack> + ".config.js" }]`
    - `SKILL.md` の生成：
      - `knowledge/<stack>/SKILL.md` が存在すればそれをコピー。
      - 存在しなければ、以下のテンプレートで生成：
        ```markdown
        ---
        name: tech-expert-<stack>
        description: <stack> に関する技術的な専門知識を提供します。
        ---
        # <stack> Expert Skill
        あなたは <stack> のスペシャリストです。`references/` 内のドキュメントに基づき、専門的な助言を行います。
        ```
    - コンテンツのコピー：
      - `knowledge/<stack>/*`（`package.json` 等のメタデータを除く）を `targetDir/references/` にコピーする。

### 3. `hooks/scripts/tech_stack_discovery_hook.cjs` の修正
- `skillsDir` の決定ロジックを以下のように変更し、`dist/skills/` を優先する：
  ```javascript
  const skillsDir = fs.existsSync(path.join(extensionRoot, 'dist/skills'))
    ? path.join(extensionRoot, 'dist/skills')
    : path.join(extensionRoot, 'skills');
  ```

### 4. ドキュメントの更新
- `docs/reference/tech-expert-spec.md` を更新し、マニュアルでのマニフェスト作成が非推奨であり、`knowledge/` への配置が標準であることを明記する。

## ゴール
- [ ] `npm run build` 実行後、`dist/skills/tech-expert-react/manifest.json` が自動生成されていること。
- [ ] 生成された `manifest.json` に適切な `detectors` が含まれていること。
- [ ] `knowledge/` に `SKILL.md` を置かなかった場合、デフォルトの指示書が `dist/skills/tech-expert-*/SKILL.md` として出力されること。
- [ ] `tech-stack-discovery-hook` が、`dist/skills/` 内の自動生成されたマニフェストを正しく認識し、セッション開始時に技術スタックを検知できること。
- [ ] 開発者が `manifest.json` を手書きする必要が完全になくなること。
