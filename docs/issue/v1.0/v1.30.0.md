# Issue: esbuild の並列化と実行オーバーラップによるビルド高速化

## 概要
`tools/build.cjs` において、`esbuild.build` を Promise 配列として一括発行し、並列実行することでビルド時間を短縮する。また、生成されるスキルのバージョン管理を最適化し、Git 履歴の汚染を防止する。

## 背景と問題点
以前のビルドスクリプトは `for...of` ループ内で `await` を使用しており、順次実行されていた。また、`manifest.json` のバージョンが実行時の日付であったため、内容に変更がなくてもビルドのたびに Git 差分（ノイズ）が発生していた。さらに、古い生成物がクリーンアップされず、削除されたソースが「ゴースト」として残る問題があった。

## 解決策
1. **段階的並列化 (Wave 方式)**: 全タスクを一斉に投げず、`hooks` -> `linters` の順に Wave ごとに並列実行することで、Windows 環境でのファイルロック競合を回避する。
2. **バージョン同期の適正化**: 実行時の日付（CURRENT_DATE）を廃止し、`package.json` のバージョン（EXTENSION_VERSION）をスキル側にも同期させる。
3. **アトミックなクリーンアップ**: 各スキルディレクトリを生成する直前に `rmSync` することで、整合性を保証する。

## 実装上の知見（不備と修正の記録）
- **Windows ファイルロック問題**: 当初、全 esbuild タスクを `Promise.all` で一斉射撃する計画であったが、Windows 環境では `user-mapped section open` エラー（ファイル競合）が発生した。対策として Wave 方式（段階的並列化）を採用し、安定性を確保した。
- **Git ノイズ対策**: 以前は `CURRENT_DATE` を使用していたが、スキルが Git 追跡対象であるため、ビルドのたびに日付の差分が発生する問題があった。これをパッケージバージョンに紐付けることで、不必要な差分を排除した。
- **ゴーストファイル対策**: 生成前に `targetDir` を個別に削除するステップを追加し、古いファイルが残り続ける問題を解消した。
