# Issue: プロジェクトルートの一時ファイルをOS標準のTempディレクトリへ集約

## 背景と問題点
スキルやエージェントが動作プロセスの中で生成・使用する一時ファイルが、プロジェクトのルートディレクトリに集約されず散乱している。この状態はワークスペースの構造を不明瞭にし、以下の課題を引き起こしている：

1. **エージェントの認知負荷**: ソースコードの調査時（`grep_search` 等）に一時ファイルがノイズとして混入し、分析精度と効率を低下させる。
2. **Git 運用の阻害**: 本来管理不要な一時ファイルが Git の追跡対象に含まれることで、差分のノイズや予期せぬコンフリクトの原因となる。
3. **ワークスペースの汚染**: プロジェクト本来の構成要素と、実行時の一時的な生成物が混在し、保守性が損なわれている。

## 解決策
プロジェクトルートに散乱している一時ファイル群を削除し、今後はOS標準の一時ディレクトリ（Windows: `$env:TEMP`、macOS/Linux: `$TMPDIR`）を使用するようツールやスキルの定義を修正する。

## 実装内容詳細

### 1. スキル定義の修正
- `skills/github-investigator/SKILL.md` 内で `temp.b64` を生成・使用している箇所（Windows 用の代替コマンド例）を、OS の一時ディレクトリ（`$env:TEMP`）を使用するように変更する。
  - 変更前: `... > temp.b64 ; powershell "...(Get-Content temp.b64 -Raw)..."`
  - 変更後: `... > $env:TEMP\temp.b64 ; powershell "...(Get-Content $env:TEMP\temp.b64 -Raw)..."`

### 2. 既存ファイルのクリーンアップ
- 以下のファイルをプロジェクトルートから削除する：
  - `temp.b64`
  - `commit_details.json`
  - `latest_build_cjs.diff`
  - `gemini-help.txt`
  - `schema.b64`
  - `validation.b64`
  - `reproduce_bug.js`
  - `reproduce_lazy_import.cjs`
  - `sample.js`
- Git のインデックスにこれらのファイルが登録されている場合は、`git rm --cached <file_path>` を実行して追跡を解除する。

## ゴール
- プロジェクトルートから上記の一時ファイルが一掃されていること。
- `skills/github-investigator` を使用した際、一時ファイルがOSの一時ディレクトリに生成されること。

## テスト
- **テスト対象**: ルートディレクトリとスキル定義
- **テスト内容・目的**: 一時ファイルが適切に削除され、スキルがOSの一時ディレクトリを利用することを確認する
- **検証方法・手順**:
  1. ルートディレクトリに `temp.b64` 等の対象ファイルが残っていないことを確認する。
  2. `git status` で対象ファイルが `untracked` かつ削除されていることを確認する。
  3. `skills/github-investigator/SKILL.md` のコマンド例を手動で実行（またはシミュレート）し、`$env:TEMP\temp.b64` が生成され、エラーなく読み取れることを確認する。

## Appendix: 技術的選定理由 (Why/Why Not)

- **Why: OS標準の一時ディレクトリ（`$env:TEMP`, `$TMPDIR`）の採用**
  - **ワークスペース汚染の防止**: 拡張機能は多様なユーザー環境にインストールされるため、OS提供の標準領域を利用することで、ユーザーのプロジェクト構成に一切干渉せずに処理を完結できる。
  - **実行環境での解決保証**: Gemini CLI の仕様上、設定ファイルやシェルコマンド内でこれらの環境変数が確実に展開・利用できることが保証されているため。

- **Why Not: プロジェクトルートへの専用一時ディレクトリ（`.tmp/`）作成の却下**
  - **他者の環境への無断介入**: 拡張機能が配布先のユーザー環境に独自のディレクトリを勝手に作成し、そこに依存するアーキテクチャは適切ではない。
  - **Git管理へのノイズ混入**: ユーザープロジェクトの `.gitignore` を拡張機能側から制御することは不可能であり、ユーザーの意図しない変更（差分）を生じさせてしまうため。
