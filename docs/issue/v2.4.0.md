# Issue: gemini-cli-expert スキルの構成刷新（catalog.json 依存の廃止）

## 概要
`gemini-cli-expert` スキルにおいて、リファレンス管理に使用していた `catalog.json` 方式を廃止する。ディレクトリ構成およびファイル名自体がその役割を果たす構成へと刷新し、`SKILL.md` の指示をそれに最適化する。

## 背景と問題点
- **中間層の弊害**: `catalog.json` という巨大な目次ファイルがコンテキストを圧迫し、情報の特定を阻害している。
- **ファイル名への集約**: 抽象的な ID 管理をやめ、ファイル名自体に具体的なコンテキストを含める（冗長化する）ことで、`list_directory` や `glob` 実行時に LLM が直接・正確に情報を特定できることが判明した。
- **保守の不一致**: 物理ファイルと JSON 記述の二重管理が、不整合の原因となっている。

## 解決策
- **カタログ廃止**: `catalog.json` を完全に廃止し、物理的なファイル名とディレクトリ構造のみでナレッジを表現する。
- **探索プロトコルの刷新**: `SKILL.md` 内の指示を、まず `list_directory` で物理構造を把握し、ファイル名から自律的に必要なドキュメントを選択・取得する形式に変更する。
- **リファレンスの冗長化**: ファイル名を「その内容が一目でわかる説明的な名称」に統一する（ユーザー作業と連携）。

## 実装内容詳細
1. **SKILL.md の改修**: (済)
   - `catalog.json` の参照手順を削除。
   - 物理的なファイル名に基づく探索ロジック（`list_directory` → `read_file`）を定義。
2. **不要ファイルの整理**: (済)
   - スキルパッケージ内の `catalog.json`（存在する場合）の削除。

- [x] `catalog.json` を介さず、冗長化されたファイル名から正確に情報を取得できること
- [x] スキルから `catalog.json` への依存が完全に除去されていること
