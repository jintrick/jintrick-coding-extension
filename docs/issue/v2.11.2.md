# Issue: `coding-rules-hook` による `hook_context` のファイル汚染を解決するための修正

## 背景と問題点
現在、`coding-rules-hook` は `AfterTool:read_file` のタイミングで `additionalContext` を使用して規約を提示しています。しかし、この仕組みには以下の致命的な問題があります。

1.  **物理的なファイル汚染**: `AfterTool:read_file` で `additionalContext` を使用すると、CLI が取得したファイル内容の末尾に物理的に規約を結合します。このため、エージェントがその規約（`<hook_context>` タグ）ごとファイルを保存してしまい、物理的なファイル内に不要なタグが残留・拡散しています。
2.  **想起タイミングの遅れ**: `read_file` の後（事後）に規約を提示しても、既に読み込みが終わっており、実際の書き込み操作（`write_file`, `replace`）の直前に規約を想起させる仕組みがないため、規約違反を未然に防ぐ効果が薄れています。

## 解決策
1.  **イベントの移行**: `AfterTool:read_file` を廃止し、`BeforeTool:^read_file|write_file|replace$` に移行する。これにより、読み込みおよび書き込みの直前に規約が提示されるようになる。
2.  **通知方式の変更**: `additionalContext` によるデータ結合（汚染の原因）を完全に廃止し、`systemMessage` による通知に切り替える。
3.  **汚染除去**: 既にプロジェクト内のファイルに混入してしまった `<hook_context>` ブロックを一括削除するクリーンアップ手順を導入する。

## 実装内容詳細

### 1. `hooks/hooks.json` の更新
- `AfterTool` セクションの `coding-rules-hook` を削除する。
- `BeforeTool` セクションに `coding-rules-hook` を追加し、マッチャーを `^read_file|write_file|replace$` とする。

### 2. `hooks/scripts/coding_rules_hook.cjs` の修正
- イベント判定を `BeforeTool` に変更。
- ツール名を `read_file`, `write_file`, `replace` に拡張。
- 規約の出力先を `hookSpecificOutput.additionalContext` から `systemMessage` に変更。

### 3. ファイル汚染のクリーンアップ
- プロジェクト内の全ファイルから、`<hook_context>...</hook_context>` のブロックを削除する。
