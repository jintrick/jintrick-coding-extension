# Claude Code エンジニアリング極意書 (Engineering Principles)

本ドキュメントは、Claude Code の 230 超のプロンプト断片から抽出された、AI エージェントを精密なエンジニアリング・ツールとして機能させるための設計哲学を体系化したものである。

## 1. 状態駆動型プロンプティング (State-Driven Prompting)

エージェントの「モード」を単なるフラグではなく、**行動の物理的制約**として定義する。

- **負の制約の優先**: 「実行してはならない」「書き換えてはならない」という制約を最上部に配置し、LLM の暴走を抑止する。
- **フェーズの不可逆性**: 理解 → 設計 → 計画 → 実行のステップを明示し、前のステップが不十分な状態での進行を禁止する。
- **リマインダーの魔力**: 履歴が長くなっても「今のフェーズ」を忘れないよう、最新メッセージの直前に短いリマインダーを動的に注入する。

## 2. 動的コンテキスト合成 (Dynamic Context Synthesis)

固定のシステムプロンプトを捨て、状況に応じてコンテキストを毎ターン最適化する。

- **ジャストインタイム注入**: ツール実行結果や現在の CWD に基づき、必要な「法典（Rules）」だけを抽出して `messages[0]` に差し込む。
- **トークン予算の格付け**: 4,000 トークンの枠内で、`Always` (憲法) > `Phase-specific` (法律) > `File-context` (事実) の順に優先順位をつけ、低優先度な情報を動的にパージする。
- **増分キャッシュ**: 100ms 以内の応答速度を維持するため、ルールのパース結果やファイルスタットをキャッシュし、変更時のみ再計算する。

## 3. ガバナンスとしてのフック (Hooks as Governance)

フックを単なる「処理の前前後」ではなく、エージェントの**思考と行動を調教するインターフェース**として定義する。

- **知覚の拡張 (BeforeModel)**: プロンプト・コンパイラを通じて、エージェントが見るべき「世界（規約）」を動的にフィルタリングする。
- **行動のサニタイズ (PreToolUse)**: 実行直前に引数を修正し、プロジェクトの規約（命名規則等）に強制的に適合させる。
- **事後検証 (AfterAgent)**: 全てのターンが終了した後に、トースト通知等で「外界（ユーザー）」へ結果をフィードバックする。

## 4. エンジニアリングの美学 (Engineering Aesthetics)

LLM に対し、単なる「回答者」ではなく「責任ある技術者」としての振る舞いを要求する。

- **Reuse over Re-invention**: 既存のユーティリティやパターンを徹底的に検索させ、安易な新規作成を禁止する。
- **Read before Write**: 修正対象のファイルだけでなく、関連する依存関係を必ず読み込み、全体像を把握してから手を動かさせる。
- **No Hacks**: 互換性のためのハックや、時期尚早な抽象化を「不純物」として排除させる。
